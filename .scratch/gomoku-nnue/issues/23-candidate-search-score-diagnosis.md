# 23: 候选子局面搜索分排序信号诊断（只读）

**What to build:** 验证「候选子局面的 depth-N 搜索分」是否含有**（a）与手工静态评估 H 显著不同、且（b）自身有区分度**的走子排序信号，以决定值不值得投入「改 datagen 记录候选搜索分 → 全量重训」。这是工单 22 收口后的方向性诊断：**不训练、不生成全量数据、不跑门控、不改动已封存产物**。

**Status:** done（诊断完成，按 §4 预声明判据判读为 INCONCLUSIVE，见 Progress Notes）
**Category:** diagnosis / read-only
**Blocked by:** 无。依赖工单 19-C 的冻结候选集 `data/m5/t19/c_real/move_cases.jsonl` 与现有 C++ 搜索引擎。
**Downstream:** 若信号成立 → 另开工单改 datagen（对每个父局面枚举候选、各跑 depth-N 搜索记录分值）并全量重训；若信号≈静态 H → 提前止损，改走其他方向（架构 / 迭代范式）。本工单不自动解除 16/10/12/11 依赖。

## 1. 为什么做这个诊断（来自工单 20/21/22 的结论）

- 工单 20：int8 权重舍入摧毁走子排序信号，float16 精度保住；M5 失败 = ① 点值回归教不会排序 ② 排序需 pairwise 损失 ③ int8 量化摧毁排序。
- 工单 21：float16 权重链路落地，点值 float16 门控 0%→30%。
- 工单 22：排序蒸馏（记录落子教师）与延长训练（20→60 epoch）均阴性，**点值目标天花板 30%**。
- 关键缺口：现有数据只记录**实际落子那条线**后续局面的搜索分（side-to-move 视角、int16 饱和 ±32767），**没有候选子局面之间的相对分**。而工单 19 已证「点值精度与走子排序解耦」——要补的是排序信号，且教师必须强于手工 H（M3 基线即手工评估 + VCF）。depth-N 搜索分是唯一同时满足「比静态 H 强」「含战术信息」「Stockfish 式 value 监督」的现成信号。

## 2. 数据源与采样（固定可复现）

- 输入：`data/m5/t19/c_real/move_cases.jsonl`（冻结验证 18,555 个 primary 父局面 + 合法非终局候选，Renju/radius1，含 `board`/`stm`/`moves`/`teacher_move`/`child_results`）。只取 `bucket=primary` 且 `child_results` 全 0（非终局）者。
- 按固定 seed 采样 **N 个父局面**（先冒烟测速再定规模，默认 ≤400），记录采样清单与输入 SHA256。不得按分数/结果挑样本。
- 候选子局面：父 `board` 在 `move` 处落 `stm` 色子，视角变为 `1-stm`。

## 3. 待测量的三个量

对同一批父局面的每个候选子局面，算两套分值（都换算成**父方视角**：`h_m = -score_child`，越大越好）：

- **H**：手工静态评估（`nnue_probe handcrafted`，工单 18/19 已用口径）。
- **S_d**：depth-d 搜索分，`d ∈ {2, 4}`。用现有 C++ `Search::findBestMove`（手工评估 + VCF + 干净 TT + 固定 depth），按 datagen 口径 `clamp(score, -32767, 32767)`（`binpack.cpp encodeScore`）。

诊断量：

1. **区分度**：每个父局面内 S_d 的 spread（std>0 的比例、非全并列比例）、`|S_d|≥32767`（饱和/mate/VCF）比例、分值分位数。
2. **H vs S 排序差异**：逐父局面 Top-1（`argmax h`）一致率、全候选 pairwise 逆序率（不一致对 / 可比对比）、按分值差距分桶的逆序率。这是主判据。
3. **跨 depth 稳定性**：S_2 与 S_4 的 Top-1 一致率、排序相关；同配置重复运行一致性（`reset()` 保证可复现，须验证）。

## 4. 预先声明的分流判据（工程分流，非因果保证；实验前固定，不得事后放宽）

- **止损信号**：depth-4 搜索分与静态 H 的 Top-1 一致率 **≥0.85** 且 pairwise 逆序率 **≤0.10** → 搜索分排序几乎等于静态 H，换数据生成预期无增益，建议不投入全量重训。
- **值得投入信号**：depth-4 与 H 的 Top-1 一致率 **≤0.60**，且搜索分自身区分度达标（非并列比例 **≥0.70**、饱和比例 **≤0.25**）→ 候选搜索分含静态 H 没有的新信息，建议开工单改 datagen。
- **中间地带**：如实报告全部指标，不强行二选一，另列补充诊断建议（例如换 depth、换教师、先做小规模可学性拟合）。

只报告描述性证据；不因某个分桶好看就宣称棋力提升或放行门控。

## Progress Notes：全量诊断结果（2026-11-06）

`data/m5/t23/full/{report.json,cases.jsonl}`：seed 20261123，300 个 primary 父局面 / 11,166 个候选子局面，`searchscore --depth 2 --tt-mb 2` 与 `--depth 4`，H 用 `handcrafted`。全部按 datagen 口径 clamp 到 ±32767、换算父方视角。`complete=true`，耗时 383.7 秒，账本 2791.438/7200 秒。CTest 20/20 全绿。

### 三个诊断量

| 指标 | H（静态） | S depth2 | S depth4 |
|---|---:|---:|---:|
| 非全并列比例 | 1.000 | 0.933 | 0.930 |
| 饱和（\|·\|≥32767）比例 | 0.007 | 0.433 | **0.444** |
| 父局面内分值 std 均值 | 2174 | 3629 | 4108 |

| H vs S | depth2 | depth4 |
|---|---:|---:|
| Top-1 一致率 | 0.371 | **0.303** |
| pairwise 逆序率 | 0.260 | 0.287 |

跨 depth（S2 vs S4，280 个有信息父局面）：Top-1 一致率 0.615、逆序率 0.103。

### 按 §4 预声明判据判读：**INCONCLUSIVE**

以最深 depth=4：Top-1 一致率 0.303（≤0.60 ✓）、非全并列 0.930（≥0.70 ✓）都满足「值得投入」，但**饱和比例 0.444 > 0.25 ✗**，因此按实验前固定的规则**不能判 INVEST**；也未触及 STOP（0.303 远低于 0.85、逆序 0.287 远高于 0.10）。不事后放宽阈值，如实记为 INCONCLUSIVE。

### 支持与未排除的解释（描述性，不作因果结论）

1. **方向假设得到支持**：搜索分排序与静态 H **显著不同**（Top-1 一致率仅 0.30、逐对逆序 0.29），且随 depth 增大差异扩大（0.371→0.303）。说明 depth-N 搜索确实含有 H 看不到的战术信息（VCF / 杀棋），「搜索分 ≈ 静态 H、换数据无增益」的止损情形被否证。
2. **暴露新的口径阻塞**：近半候选（0.444）饱和到 ±32767；只读复核 `cases.jsonl` 显示 **43.3% 的父局面至少 1 个饱和子局面、39.3% 有 ≥2 个候选并列在同一饱和值上而无法排序**，平均每个父局面 38.4% 候选饱和。这正是工单 12/19 反复出现的「饱和搜索分标签」问题在候选层面的放大——**int16 clamp 把 mate/VCF 分压成同一个值**，排序信号被压平。
3. 仍有 **56.7%（170/300）父局面完全无饱和**，其中搜索分排序是干净的；跨 depth 稳定性中等（Top-1 0.615）。信号存在但被标签口径污染，二者并存。

### 下一轮单变量建议（另开工单，本工单不实施）

若要改 datagen 记录候选搜索分，**必须同时改标签口径**——不 clamp 到 int16，改用更宽范围、WDL 或 mate 距离，否则会重演饱和坑。建议先做一个小规模可学性拟合：仅用「无饱和父局面」的候选搜索分做 pairwise 排序监督（float + float16），确认该干净子集能教会排序，再决定是否投入全量数据生成。仍不扩网、不消耗正式开局、不解除 16/10/12/11 依赖。
