# 20: QAT 排序学习受限——量化/STE 训练路径在 pairwise 排序损失下失效的诊断

**What to build:** 定位为什么独立 float 能在 pairwise 排序损失下学会候选排序，而 QAT（STE + int8 权重 + int16 累加器）在同一损失、同一数据、同初始化下学不动（排序仍随机）。区分 STE 梯度偏置、量化权重更新卡死、累加器尺度、有效学习率等并列解释，给出可操作的量化方案或训练策略修改建议。不改动已封存的工单 18/19 源码与产物，不扩网、不加数据、不消耗正式开局。

**Status:** 规范已交付（诊断未实施/未运行）

**Blocked by:** 无。依赖本会话已交付的 C 冻结 manifest（`data/m5/t19/c_real/c_manifest.json`）与 `trainer/local_ranking_pair.py`。
**Downstream:** 决定最终 NNUE 部署的训练路径（QAT vs 浮点 master + 导出量化 vs 其他）；本工单不自动解除 16/10/12/11 依赖，也不运行正式比赛。

## 1. 已知证据

- **排序损失实验（本会话 stage R）**：同一 64 primary 父 / 2,300 子、同一 pairwise logistic（RankNet）损失、同初始化/批次/投影：
  - float 10k 步：pair disagreement `0.489 → 0.267`（仍在下降）、teacher-best excess `0.03 → 0.16`；
  - QAT 1k/10k 步：disagreement `0.486`、excess `0.010`，仍随机。
- **点值对照（工单 19 B/C）**：独立 float 与 QAT 在点值 Huber 下的拟合比，float 始终优于 QAT（B `0.17 vs 0.42`；C `0.26 vs 0.49`）。
- **工单 17（已关闭）**：点值下隐藏层确实在学（accumulator/L1 L2 变化 `0.12–0.16`、`changed_fraction≈1.0`），削弱「隐藏层冻结」朴素假设；但未测排序损失下的机制。

## 2. 待区分假设（并列，不预设）

- **H1 STE 梯度偏置**：量化前向的 straight-through 估计在排序损失下梯度方向失真。
- **H2 int8 权重更新卡死/粒度太粗**：量化后整数权重逐步跳变幅度过小或过稀，排序所需的精细变化被舍入抹掉。
- **H3 累加器/激活 int16 尺度**：中间累加器饱和或量化尺度与排序损失不匹配。
- **H4 有效学习率/优化器**：量化后梯度被放大/缩小，实际有效 lr 偏离设定值。

## Progress Notes：量化算术崩塌排序（2026-11-06）

新增 `trainer/qat_ranking_diag.py`：同一 64 父 / 2,300 子，对同一 checkpoint 分别跑浮点前向与整数前向，比较排序。实测：

| checkpoint | float 前向 disagreement | 整数前向 disagreement | float excess | 整数 excess |
|---|---:|---:|---:|---:|
| float 训练 10k 步 | **0.267（学会）** | **0.482（崩回随机）** | 0.160 | -0.031 |
| float 训练 + quant-reg 1.0 | 0.275 | 0.483 | 0.191 | -0.039 |
| QAT 训练 | 0.463 | 0.486 | 0.025 | 0.010 |

**关键结论（已收窄）**：

1. **浮点网络能学排序**（disagreement 0.267），**但 int8 整数前向把它崩回随机**（0.482）。
2. **权重舍入不是主因**：float 权重离整数很近（roundtrip drift max ≤0.5、mae 0.03–0.36），且 quant-reg 1.0 训练后整数前向仍是随机——排除「权重小数差异被舍入抹掉」的解释。
3. **嫌疑集中在整数算术本身**：`round_div` 整数除法、int16 累加器 clamp、激活 `[0,qa]/[0,qb]` clamp 中至少一项把排序信号抹掉了。这正是原 H3（累加器尺度）+ 新证据（整数除法精度）的方向。

**下一步（待实施）**：对前向做逐项消融——在「权重已量化」的前提下，分别单独关掉 round_div（改浮点除法）、关掉累加器 clamp、关掉激活 clamp，定位到底哪一步崩掉排序。据此决定量化方案修改（更高精度 / 更细除法 / per-channel 尺度）。

## Progress Notes：消融定位到权重舍入（2026-11-06）

新增 `trainer/qat_quant_ablation.py`，对 float 训练的模型交叉两个旋钮（权重舍入 × round_div）做四种前向：

| 前向变体 | disagreement | excess |
|---|---:|---:|
| float 权重 + float 除法（全浮点） | **0.267（学会）** | **0.160** |
| 舍入权重 + float 除法 | **0.486（随机）** | -0.023 |
| float 权重 + round_div | 0.425（半崩） | 0.010 |
| 舍入权重 + round_div（全整数） | 0.482（随机） | -0.031 |

**根因定位**：**权重舍入（int8）是主凶**——单这一步就把排序 0.267 → 0.486 崩回随机；round_div 整数除法是次要帮凶（0.425）。排序信号藏在权重的**小数部分**（drift ≤0.5 但不可舍去），int8 整数前向无法表示这种精细相对信号。这解释了整个 M5 失败：部署用的 int8 前向让引擎下出接近随机的棋。

**下一轮单变量建议**：把量化网格变细（权重保留 1–2 位小数，即定点小数 / 更高精度如 int16 权重 / per-channel 尺度），验证排序能否在量化后存活。这将是量化方案层面的修改，需另封存新权重格式契约并重做跨语言对齐。
