**Current behavior:**

首轮 7,208 条 / 280 局数据上的 NNUE，在旧 100 局 depth-2 门控中为 0 胜 / 0 和 / 100 负。三组重训没有给出足够证据排除数据或优化问题。已有前向支持浮点和 STE，但缺少固定无增广小样本的拟合诊断；常规训练按验证损失选 checkpoint，不能直接替代同样本记忆实验。

现有导出报告中，训练原模型 vs 未校准整数模型 MAE 27.3509 / max 71.10513。最终约 0.36 的 MAE 比较的是导出权重重建模型与整数推理，证明算术一致性，未衡量训练原模型到最终导出的保真度。现有 runner 使用 >= 阈值，逐局生成开局，未记录实际后端或权重身份。datagen 的预算参数只报告 ETA，不会到时停止。

**Desired behavior:**

先实现和运行可明确限时的短检查；预计超过 5 分钟或无法可靠估时的训练、数据生成、批量对打，提供用户可执行的命令、日志和结构化报告，交用户启动。首轮各实验任务实际墙钟耗时累计不超过 7,200 秒；并行 worker 不重复累计。保存跨命令的预算使用记录，剩余预算不足时不启动任务；限时机制应清理所启动的子进程并标记不完整产物，不能把中断结果当作完整验收。

诊断分阶段推进，每阶段读取结果后再选择后续实验：

1. **固定小样本拟合。** 固定样本、行棋方覆盖、seed 与标签变换，关闭随机 D4，报告训练同样本上的 float / STE 拟合曲线及输出、激活/梯度的必要统计。同样本拟合仅用于可学习性诊断，不称为泛化。若拟合失败，优先定位梯度、优化或数值限制，保留证据后才提出网络修改。
2. **训练到导出保真度。** 在相同评估样本上，分别比较训练原模型、STE、未校准整数、最终校准整数，以及 C++ 推理；报告原始搜索分单位和同一目标空间中的误差/任务损失。校准样本与独立评估样本按完整对局分离，保存各自样本身份。将算术对齐与训练到量化的效果保留分开呈现。
3. **同口径基线与独立数据。** 从训练集拟合常数预测和 WDL 类别先验，在完全相同的验证记录及目标变换上评估模型/基线，报告误差比值。需要扩大数据时使用新 RNG 流、记录来源、按完整对局划分，并固定其他条件；不能把同 seed/分片配置的校准数据当成独立增量。扩大多少数据由已有证据与剩余预算决定，不先承诺千万规模。
4. **候选与正式门控。** 小批量比赛仅筛选。正式比赛冻结 100 个随机开局，每个开局交换引擎先后手，共 200 局；开局与训练生成流程分离，不根据正式比赛结果挑选。双方使用同一引擎构建、Renju、depth 2、VCF 开启和 64MB TT，仅评估器不同；NNUE 默认 AVX2。得分率 `(wins + 0.5*draws)/games` 严格大于 0.65 才通过，按未舍入计数判断。记录完整对局、开局配对、命令/设置、seed、源码版本/工作区状态、exe/权重校验和和 ABOUT 的实际后端；请求 NNUE 却回退手工评估时中止该验收，不得作为候选晋级证据。

允许按诊断证据修改架构、训练目标、优化或量化尺度；尽量保留既有权重格式。训练侧改动若不改变张量布局、输出单位及推理语义，不要求升级格式；确实变化时同步更新版本/契约与导出、跨语言验证，保留旧产物复现。所有试验产物单独归档，不覆盖原参照权重。输出单位的变化不能仅作为训练损失调整处理。

**Key interfaces:**

- `NNUEModel.forward(..., quantized=False|True)` / `mixed_losses()`：分别测量浮点、STE 和任务目标，诊断模式要能固定样本与增广条件。
- `NNUEModel.quantized_weights()` / `from_quantized_weights()` / `infer_int()`：明确原训练模型与导出模型身份，避免用重建参照替代训练到导出保真度。
- `Search::setNetwork()` / `ABOUT`：确认比赛实际使用的评估器；复用现有 C++ probe 做算术验证。
- `MatchConfig` / runner 报告：支持可复核的相同开局交换先后手、严格门控和产物身份。
