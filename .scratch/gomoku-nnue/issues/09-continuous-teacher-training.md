# 09: 持续教师训练闭环

**What to build:** 用户启动教师训练任务后，采集、Rapfi 打标、样本池训练与周期历史测评持续推进，通过评测的新模型供后续采集和实际对弈使用。

**Blocked by:** 05 — 持续采集与滚动样本池；08 — 历史版本测评与晋级。

**Status:** done

- [x] GUI 提供单次启动的教师训练任务，复用已交付的采集、样本池、训练、导出、部署及评测能力，不另造平行流程。
- [x] 数据就绪后训练可与采集打标并行；采集过快或数据不足时限速、等待或背压，不无限增长磁盘或对同一批数据无约束反复训练。
- [x] 启动样本量、训练与采集比例、候选产生周期、资源限制和停止条件可配置并记录，不以数百万条数据为训练前置条件。
- [x] 尚无模型时使用既定启动采集策略；建立 v0 后，自我对弈采集使用已发布正式版本的固定快照。
- [x] 每盘棋开始时绑定模型身份，候选训练独立更新；正式版本晋级只影响后续新对局，不在盘中热换权重。
- [x] 定期产生候选，先完成导出和数值检查，再使用冻结配置挑战正式版本；未通过时继续使用现任版本。
- [x] 采集、教师、训练及比赛拥有明确任务状态，GUI 显示阶段、有效吞吐、样本容量、训练指标和测评结果。
- [x] 标签来源、数据提交身份、模型谱系和晋级报告相互关联，能够复查候选从哪些数据产生。
- [x] 公共编排能力按数据生产、标签来源、训练和评测职责组织，后续自主模式能够复用并替换教师监督来源。

- [x] 提供安全停止，结束所启动的子进程并保留已提交数据和有效模型；完整暂停恢复由后续工单补齐。

### 实施与验收记录（2026-11-10）

**公共编排边界**

- `tools/training_task.py`：`TaskConfig` 冻结配置，`TrainingTask.run()` / `stop()` / `snapshot()` 统一运行、停止与状态。`TeacherDataSource` 单独负责教师依赖和监督来源；调度器通过 `preflight()` / `produce()` 接入数据源，训练和比赛复用现有 `train_value()` / `evaluate()`，后续自主监督无需重写调度循环。
- 单个生产线程与候选训练/测评并行。任务持有样本池 lease，记录采集、教师、训练和比赛状态；数据源故障、依赖缺失或比赛异常明确失败，已提交数据与正式版本不被删除。
- 启动前冻结引擎副本、教师锁身份、资源、完整参数、Python/PyTorch/HIP/CUDA/GPU 环境、实现文件哈希和初始正式版本。`manifest.json`、`state.json`、`events.jsonl` 与逐轮 `round-*.json` 保留可复查记录。

**数据、背压与谱系**

- 每盘重新读取正式登记表并核验实际加载模型；没有模型时明确使用手工评估。盘内 C++ 进程持有固定模型，晋级只影响下一盘，不把训练中的候选用于采集。
- 采集配置记录 task id、model id / SHA-256 / 正式版本，提交事件关联 source ids、pool run id 和提交序号。停止的暂存对局明确中断，不记录为新提交。
- `SamplePool.training_snapshot()` 在同一 WAL 事务中读取训练、验证、状态与计数；训练接收不可变内存快照，淘汰不改变正在使用的输入。数据指纹覆盖实际棋盘、标签和来源，不再仅哈希行号。
- 新增单调 `commit_sequence` 与 `committed_training_samples`，只在提交事务中更新。第一轮满足启动阈值即可开始，后续必须有足够新提交训练样本且指纹变化；暂存样本、去重失败和未变化的数据不会触发无限重训。
- 有限快照支持新旧混合；“最新”按 AUTOINCREMENT 样本写入顺序判断，不依赖来源名称或数字种子的字符串顺序。相关回归先复现了旧实现把最旧样本当最新的问题，再修复并通过。
- checkpoint 与模型元数据保存本轮任务/父模型/当时正式版本/数据提交谱系。任务内续训上个合格候选；从已有正式版本首次启动时，用其量化权重初始化浮点网络，建立新优化器，继承已经验证的训练清单。数值不合格不进入测评，未晋级保持现任。

**默认限制（全部赛前记录，可配置）**

- 池容量 1000；启动需 32 条训练和至少 1 条验证样本；后续每轮至少 32 条新增已提交训练样本。每轮 200 步、批 32，最多使用 512 条训练样本，新旧比例 0.5，轮间至少 10 秒。
- 训练样本积压达到 128 时暂停生产；常规局间等待 100 ms，高利用率时 500 ms。一个采集线程、教师/引擎单线程，PyTorch CPU 线程 2，设备默认 auto（AMD / NVIDIA / CPU 共用）。
- 最多 10 个候选、1000 次采集或 60 分钟；连续 50 盘无有效入池样本、数据长期不变也会结束/停止并报告原因。没有百万数据门槛。
- 普通候选目录保留最近 3 个，额外保护最后合格的续训 checkpoint；正式登记及晋级证据独立保留。任务有明确次数/时间上限，不靠无限增加磁盘维持。

**停止与客户端**

- 「持续教师训练闭环」面板一次启动，展示阶段、累计样本/池容量/吞吐、采集模型、优化与验证指标、资源、正式版本和测评结论；运行时阻止其它界面任务抢占。
- 停止或关闭窗口设置公共取消信号，保存真正完成的优化步骤和当前导出，回收所拥有的执行器/教师进程，丢弃未提交对局。完成清理后才解除界面忙碌状态；已有正式版本保留并可直接用于对弈。
- 顺带修正训练停止时多记一步，以及实际批量小于配置批大小时高估曝光的旧问题；新增公共训练边界回归，验证停止后只计已执行优化、曝光按实际批量计算。
