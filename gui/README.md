# 桌面对弈客户端（工单 02）

Windows 本地客户端：选择执黑或执白，与现有引擎完成一局有禁手五子棋，查看合法落点、禁手原因、着法记录、对局结果与重放校验，并可随时开新局。

## 框架与本地控制方案

- **GUI 框架：PySide6 6.9.3**（Qt for Python）。控件与信号槽完整，适合后台任务与长时间运行；与 `trainer/` 和 `tools/` 同为 Python，后续采集、自我训练、测评工单可以直接复用同一套后端客户端。依赖已写入根目录 `requirements.txt`，离线可运行。
- **控制协议：JSON-lines over stdin/stdout**。GUI 通过 `tools/executor.py` 启动 `gomoku_nnue.exe --executor`，每行一个 JSON 请求、一行一个 JSON 响应。原 Gomocup 协议保持不变，仍供引擎对引擎对战使用。
- **权威执行器**：所有规则（完整合法落点、禁手原因、落子结果、终局）只由 C++ `Executor` 给出。GUI 和 Python 客户端不实现任何禁手或胜负算法。

| 命令 | 作用 |
|---|---|
| `about` | 引擎身份、实际评估方式及新模型的模型 id/架构/规则/特征/价值契约；手工评估不会标成已训练 NNUE |
| `new_game` | 15×15、黑先白后、自由开局的新局 |
| `state` | 棋盘、行棋方、结果、规则、着法历史快照 |
| `legal_moves` | **完整**合法落点集合，以及每个禁手点的具体原因 |
| `move_reason` | 单点合法性及拒绝原因 |
| `play` | 落子；非法请求或终局后落子不改变棋盘、行棋方或历史 |
| `undo` | 撤销上一手 |
| `rebuild` | 局面重建与校验（拒绝损坏输入；报告是否与黑先行棋一致） |
| `replay` | 从空棋盘重放着法序列，得到一致终局 |
| `candidates` | 搜索候选裁剪，明确区别于完整合法落点集合 |
| `vcf` | 对当前局面做一次开源 VCF 算杀查询：状态、首着、变化、结束证据、预算与实际开销 |
| `think` | 引擎选点（只返回着法，不落子），GUI 再显式 `play`；结果附带本轮算杀状态与调用点 |
| `quit` | 结束执行器进程 |

## 行为约定

- 引擎思考放在后台线程，主线程只负责界面；思考期间不向执行器发其它请求，界面仍可响应「新局」「停止对局」和关闭窗口。
- 「停止对局」和关闭窗口会终止引擎子进程并按需重建，不留下后台工作进程；引擎侧诊断与协议错误在状态区明确显示。
- 「模型与评估方式」面板列出 `weights/` 下的 `*.gmvalue` 并能浏览选择；「应用模型」启动带 `--value-model` 的新引擎进程并开始新局。界面显示实际加载的模型 id、架构、规则/特征/价值契约与「候选试玩（未晋级正式版本）」，加载失败时保留当前可用的引擎进程并明确报错，绝不把失败模型显示为已加载。
- 没有模型时显示「手工威胁评估（没有加载已训练模型）」；加载旧版 NNUE 时显示后端与权重路径。手工评估不会被标记为已训练 NNUE。
- 双击 `play.bat` 默认加载 `weights/registry/state.json` 中的当前正式版本；`--model` 显式选择候选。模型面板区分候选、当前正式版本和冻结历史版本，哈希校验失败时明确报告。
- 「历史版本测评与晋级」面板选择候选和额外历史对手，当前正式版本自动参与挑战；可设置开局对数、双方相同的每步时间和得分率基线。数值检查和一对合法完整对局通过后可登记 v0；后续只有所有对手均通过冻结的统计门槛才原子晋级。可查看胜和负、得分率、严格胜率、有效局数、配对下界、异常和报告路径；证据不足、失败或停止时均保留原正式版本。详见[根目录说明](../README.md#历史版本测评与晋级工单-08)。
- 测评在后台运行，界面可滚动查看各面板；「停止测评」保存部分报告并结束比赛进程。测评期间不允许切换对局、模型或开始其它任务。
- 一局结束后自动用同一执行器重放着法序列并显示校验结果。
- 状态区显示算杀引擎身份（`quintet@commit`）；「算杀检查（VCF）」按钮在后台线程查询当前局面，显示已证明/未证明/预算耗尽/中断、首着、变化、预算与实际开销；查询期间界面保持响应，「停止对局」会终止引擎进程，结果按未知处理。
- 引擎每步的 `think` 响应也会带上本轮算杀状态：`proven` 且首着合法时引擎直接走该着法，其余状态不改变正常评估。
- 「持续采集」面板选择局数与容量、设定教师预算后启动后台采集，实时显示生成/有效/入池/池容量/有效每秒与过滤原因；「停止采集」让当前对局中止并被丢弃，不遗留采集或教师进程。
- 「价值网络训练」面板选择样本池、步数/批大小/学习率/损失，后台训练并显示训练/验证损失、验证 MAE、导出保真度和模型路径；「停止训练」保存 checkpoint 并导出当前模型，关闭窗口会先停止训练线程。
- 「持续教师训练闭环」面板一次启动采集、教师打标、候选训练与历史测评，可配置启动/新增样本量、容量、每轮训练预算、设备和结束条件。采集与训练并行；晋级只影响下一盘采集。界面显示阶段、池累计计数、吞吐、采集模型、训练/验证指标、资源及测评结论。停止或关闭窗口会保留已提交数据和正式模型，并等待所启动进程退出；操作与默认值见[根目录说明](../README.md#持续教师训练工单-09)。
- 当前该面板名为「持续训练：教师 / 自主」，可显式选择教师训练、自主过渡或完全无教师。自主模式需要已有正式版本；过渡允许按权重使用历史教师样本，完全无教师同时排除训练/验证的教师标签。新增自对弈时间、探索概率和历史教师权重控件；界面说明所选模式、实际来源与总池/可用容量。教师不可用时自主任务仍可启动，停止后不会静默切回教师。
- 尚无正式模型时，自主模式在启动前提示先建立 v0，不创建失败任务；点击「先建立 v0：切换到教师训练」只切换选择，再点击「启动教师训练任务」。等正式版本显示 v0，停止并等待任务结束后，才切回自主模式启动。已有合格候选也可用历史测评面板「验证并登记 v0」。
- 状态区显示本地 Rapfi 教师的身份与安装状态（版本、Renju 权重、标签版本）。「打标并保存样本」在后台线程用独立执行器校验当前局面、跑 VCF 过滤、调用教师并把结果写入 `data/teacher/samples.sqlite3`，面板显示原始评分、归一化价值、过滤原因、教师状态、预算与有效样本数；教师缺失或哈希不符时明确报错，绝不产生假标签。

## 启动

先按根目录 `README.md` 用 venv 的 cmake + Ninja 构建出 `build/engine/gomoku_nnue.exe`，然后任选一种：

~~~text
双击 gui\play.bat
.venv\Scripts\python.exe gui\gomoku_gui.py
.venv\Scripts\python.exe gui\gomoku_gui.py --engine build\engine\gomoku_nnue.exe --movetime 800
.venv\Scripts\python.exe gui\gomoku_gui.py --engine build\engine\gomoku_nnue.exe --model weights\value-demo\model.gmvalue
~~~

也可用环境变量 `GOMOKU_ENGINE` 指定引擎路径。

`--pool PATH` 指定采集与训练的默认样本池，`--collection-seed N` 固定采集输入以复现问题；默认种子随启动任务变化。

## 验证

- `engine/tests/executor_tests.cpp`：执行器 C++ 行为（非法请求不改状态、终局拒绝、撤销、规则分类、D4、重放一致）。
- `engine/tests/executor_blackbox.py`：通过 JSON 协议黑盒验证完整落点、禁手原因、非法不改状态、终局拒绝、完整对局重放一致与进程清理。
- `engine/tests/vcf_tactics_tests.py`：算杀适配边界的可复用打标接口（不需要 GUI）。
- `engine/tests/gui_vcf_smoke.py`：offscreen 下构造真实窗口，验证算杀状态、首着、变化、预算与停止后的未知显示。
- `engine/tests/gui_teacher_smoke.py`：offscreen 下验证教师身份、真实打标后显示评分/过滤/有效样本数，以及教师缺失时报错且不落盘。
- `engine/tests/gui_collect_smoke.py`：offscreen 下启动真实小批量采集，验证指标、样本池写入、停止后回到空闲且无暂存对局。
- `engine/tests/gui_train_smoke.py`：offscreen 下启动真实训练，验证进度、验证 MAE、导出保真度与停止后仍保存 checkpoint/模型。
- `engine/tests/gui_model_smoke.py`：offscreen 下验证模型选择与身份显示、新模型真实落子、切回手工评估、损坏模型被拒绝且不伪装、启动时加载失败明确显示。
- `engine/tests/gui_history_smoke.py`：真实 v0 登记、后台测评、证据不足不晋级、停止、版本身份和新窗口默认加载正式模型；所有模型、登记表与报告使用隔离临时目录。
- `engine/tests/gui_training_task_smoke.py`：从空池一键完成真实采集、候选、v0、历史挑战与拒绝晋级，再验证停止、任务冲突保护、正式模型加载及进程清理。
- `engine/tests/gui_selfplay_smoke.py`：教师不可用时从混合池启动完全无教师任务，验证真实候选与历史测评、来源隔离、保留现任、停止和显式模式切换。
- 以上均注册在 `ctest`；界面验收覆盖选色、新局、引擎响应、合法落点/禁手原因、着法记录、结束重放校验、算杀面板、模型选择与退出清理。
