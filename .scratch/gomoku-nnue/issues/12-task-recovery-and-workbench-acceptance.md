# 12: 任务恢复与一站式验收

**What to build:** 用户在同一个 Windows 客户端管理对弈、采集、从零训练、教师训练、自主训练和测评，能够安全暂停、恢复和停止任务，并在重启后继续未完成工作。

**Blocked by:** 10 — 完全无教师自主训练；11 — 增量累加器与推理加速。

**Status:** done

- [x] GUI 统一提供“玩一把”“收集数据”“从0训练”“自我训练”“测评”和模型选择，显示实际模式及正式、候选版本身份。
- [x] 长任务均通过公共编排边界运行，界面保持响应；能够查看阶段、有效样本量、池容量、训练进度、资源配置和比赛结果。
- [x] 任务状态区分运行、暂停中、已暂停、完成、失败和已停止；暂停在安全的数据或训练检查点生效，不仅改变按钮文字。
- [x] 恢复信息绑定模型与优化器、随机状态、训练进度、样本池提交身份、任务和标签配置；恢复前核验兼容性。
- [x] 对采集、训练和比赛明确暂停恢复边界；进行中的棋局或评测配对如需重启，明确标记并按原冻结配置重做，不能伪造已完成结果或重复计分。
- [x] 关闭客户端或显式停止时回收其工作进程；重启后能够从有效状态恢复，不能重复回填胜负、读取半写入数据或重复发布同一候选。
- [x] 资源配置和并发任务冲突有可见处理，背压与停止条件生效；已提交数据和现任模型不因任务失败受损。
- [x] 恢复后仍保持验证集、价值契约、模型谱系和评测配置一致；不通过恢复动作重新抽取更容易的验证或比赛数据。
- [x] 完成小规模真实端到端验收：教师启动得到 v0、实际对弈、持续数据与候选训练、历史测评、完全禁用教师的自主训练、暂停恢复及停止。
- [x] 最终报告区分链路正确性、数值保真度、性能和棋力证据；没有实际晋级时如实记录，不宣称持续变强。
- [x] 更新实际安装、启动、任务操作和故障恢复说明，使新环境用户可以在本地运行交付工作台；不把尚未实现的按钮写作已可用。

## Verification

以 GUI 可见操作和公共任务编排为最高验收边界，补充重启、中断、依赖缺失、数据不完整和恢复配置不符场景。外部可观察结果与持久状态相互核对。

### 实施与验收记录（2026-11-11）

**统一工作台**

- `gui/gomoku_gui.py` 右侧改为「玩一把」「收集数据」「从0训练 / 自我训练」「测评」四个标签页；棋盘常驻左侧，模型选择固定在标签页上方。原有对弈、教师打标/采集、价值网络训练、持续教师/自主任务和历史测评面板全部保留，只是按流程归入标签页；没有删除或重写底层能力。
- 每个流程继续显示实际 `model_id`、架构、规则/特征/价值契约和后端；持续任务面板显示模式、监督来源、权重、池容量、候选轮数、训练进度、资源与测评结论。
- 持续任务状态为 `created / running / pausing / paused / resuming / stopping / stopped / completed / failed`，GUI 显示中文状态；暂停、继续、停止按钮按状态启用，而不是只改文案。

**暂停边界**

- 采集：`TrainingTask` 生产线程在整盘之间等待 `pause_event`；`collect.collect()` 的独立面板同样在每盘之间等待。暂停不会在提交事务中间发生。
- 训练：`train_value()` 新增 `pause_event`，在优化步边界停止并保存包含模型、优化器、步数、历史、数据身份、训练局面、血统和 Python RNG 状态的 `last.pt`。恢复使用同一 checkpoint 继续到原目标步数。
- 测评：`history_evaluation.evaluate()` 新增 `resume_run`。暂停通过 `stop_event` 在整对边界中断，report 标记 `interrupted`；恢复时复用原 run 目录、候选/对手副本、引擎副本、冻结开局和配置，丢弃上次未完成的配对付费结果并整对重做。不会把半盘棋计入统计。
- 独立 GUI 面板：采集支持暂停/停止；从0训练支持暂停并从 `last.pt` 继续；历史测评支持暂停后「继续上次中断的测评」。

**恢复契约**

- 新任务目录写入 `manifest.json`：完整 `TaskConfig`、监督来源、冻结引擎副本身份、初始正式版本、实现文件身份与运行环境。恢复必须与 manifest 配置完全一致，否则明确拒绝。
- 每轮开始前把实际训练/验证样本、价值契约、损失权重、样本池提交序号与 `samples_sha256` 冻结到 `rounds/round-NNNNN-bundle.json`。恢复训练只读该 bundle，不因池新增/淘汰重新抽样，也不重新抽取验证集。
- `last.pt` 和 checkpoint 的配置/数据身份在 `strict_resume=True` 下核验；数据快照不匹配、架构或价值契约不符都会失败。RNG 状态随 checkpoint 保存并在恢复时还原，避免重复/跳过的采样序列。
- 生产者在启动每盘前持久化 `next_game`，崩溃或重启不会复用同一 game index/source id；恢复时清理上次进程遗留的 staged 对局。同一任务异常退出后，旧 lease 在 PID 不存在时由 `resume_from_directory()` 接管；PID 仍存活则拒绝并发写池。
- 测评发布前检查现任版本 SHA-256：同一候选已是现任时只报告 `candidate already current`，不重复创建版本；发布本身仍使用原 `ModelRegistry.publish()` 的 compare-and-swap 校验。发布失败、证据不足或任务停止都保留现任模型。

**测试**

- 新增 `engine/tests/recovery_tests.py`：训练中暂停到检查点并原地恢复完成；停止后用新 `TrainingTask` 对象从同一目录重启，接管 stale lease、清理 staged 对局、保留冻结验证集与数据身份；修改配置恢复被拒绝；测评暂停后复用同一冻结 run 续跑并只发布一次。
- 新增 `engine/tests/gui_recovery_smoke.py`：offscreen 验证四个标签页、真实教师任务在优化步暂停/继续完成 v0、关闭窗口回收 worker/子进程、重启窗口发现任务目录、恢复未完成任务、保留 v0 不重复发布。
- 扩展 `history_evaluation_tests.py`：中断后恢复使用同一 run/开局、整对重做、只发布一次；已发布候选再次恢复不新增版本；冻结文件缺失/被改或 manifest 被重写时明确拒绝。
- 扩展 `gui_history_smoke.py`：在真实测评中断，点击「继续上次中断的测评」，验证复用同一 run、完成后保留现任 v0。
- 扩展 `value_train` 测试/恢复路径：checkpoint 增加 RNG 状态；普通 CLI warm start 仍可换新池（默认非严格），完整任务恢复启用 `strict_resume` 绑定冻结数据。
- 全量 CTest **41/41 通过，无跳过**（最终一轮 121.07 s）；`git diff --check` 通过。

**小规模真实端到端验收**

以下均在本机真实运行（Windows 11，i7-14700KF，固定 Rapfi 250615 与真实 C++ 执行器；隔离临时目录，不动生产登记表/样本池）：

- `gui_training_task_smoke`：空池启动真实教师任务 → 采集、打标、候选训练 → 登记 v0 → 历史挑战证据不足保留 v0 → 窗口实际加载 v0 对弈；停止后回收 worker/教师/引擎，已提交数据与现任保留。
- `gui_recovery_smoke`：真实教师任务训练中暂停 → 检查点恢复 → v0；关闭客户端回收进程并保留暂停检查点；新窗口发现任务目录并恢复未完成任务，版本数仍为 1。
- `selfplay_task_tests`：阻断教师适配器和 Rapfi 进程后，完全无教师模式仍完成真实自对弈、结果入池、候选训练、导出和历史测评；截断/中断/超时/崩溃/非法着法不产生标签，正式版本保持。
- `recovery_tests`：覆盖训练/评估暂停边界、重启、残留数据、配置不符和验证集冻结。日志在 `build/acceptance/ticket12/`（构建产物，可重新生成）。

**结论边界**

- 链路正确性、数值保真度和暂停/恢复行为有独立测试；本轮没有产生足以晋级的新候选，`gui_training_task_smoke` 的第二次挑战仍按低于冻结门槛保留 v0。报告不宣称棋力提升或持续变强。
- 性能只报告既有增量推理/搜索实测和本轮 CTest 时长；不把恢复功能的开销或任务完成时间当作棋力或吞吐承诺。
- 恢复依赖任务目录完整（manifest、state、冻结 bundle、checkpoint、候选/测评目录）。目录被手工删改会明确失败，不会猜测性续跑。
- GUI 的标签页整合复用现有后端；独立采集/训练面板的暂停粒度分别是整盘和优化步，持续任务是教师/自主训练的主入口。
