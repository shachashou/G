# 09: 持续教师训练闭环

**What to build:** 用户启动教师训练任务后，采集、Rapfi 打标、样本池训练与周期历史测评持续推进，通过评测的新模型供后续采集和实际对弈使用。

**Blocked by:** 05 — 持续采集与滚动样本池；08 — 历史版本测评与晋级。

**Status:** ready-for-agent

- [ ] GUI 提供单次启动的教师训练任务，复用已交付的采集、样本池、训练、导出、部署及评测能力，不另造平行流程。
- [ ] 数据就绪后训练可与采集打标并行；采集过快或数据不足时限速、等待或背压，不无限增长磁盘或对同一批数据无约束反复训练。
- [ ] 启动样本量、训练与采集比例、候选产生周期、资源限制和停止条件可配置并记录，不以数百万条数据为训练前置条件。
- [ ] 尚无模型时使用既定启动采集策略；建立 v0 后，自我对弈采集使用已发布正式版本的固定快照。
- [ ] 每盘棋开始时绑定模型身份，候选训练独立更新；正式版本晋级只影响后续新对局，不在盘中热换权重。
- [ ] 定期产生候选，先完成导出和数值检查，再使用冻结配置挑战正式版本；未通过时继续使用现任版本。
- [ ] 采集、教师、训练及比赛拥有明确任务状态，GUI 显示阶段、有效吞吐、样本容量、训练指标和测评结果。
- [ ] 标签来源、数据提交身份、模型谱系和晋级报告相互关联，能够复查候选从哪些数据产生。
- [ ] 公共编排能力按数据生产、标签来源、训练和评测职责组织，后续自主模式能够复用并替换教师监督来源。
- [ ] 小规模真实任务至少走通一次候选产生和评测结果处理；评测不通过仍可正确结束或继续，不要求为演示强行晋级。
- [ ] 提供安全停止，结束所启动的子进程并保留已提交数据和有效模型；完整暂停恢复由后续工单补齐。

## Verification

在公共任务编排边界运行低预算真实闭环，检查并行采集训练、样本背压、模型快照、晋级与拒绝分支和安全停止。
