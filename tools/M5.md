# M5 分阶段诊断与用户运行指南

工单 12 的工具准备阶段。先读每阶段结果再选择下一项实验；这些命令不会自动串联训练、自举或晋级。所有命令从仓库根目录执行，使用项目 `.venv`。

## 运行约定

预计超过 5 分钟或无法可靠估时的任务由用户启动。统一使用 `tools/budget_run.py`，共用 `data/m5/budget.json`，首轮累计上限 7,200 秒。`--seconds` 是该任务的实际硬上限，不是预计耗时；若剩余预算不足以容纳整个请求则拒绝启动。启动前预留时间，结束后按整项任务实际墙钟计时结算，并行 worker 不重复收费。

每次使用新的 `--out-dir`；运行器和诊断工具都拒绝覆盖已有实验。`console.log` 保留 stdout/stderr，`run.json` 记录命令、源码状态、耗时、退出码和完整性。Windows 使用 Job Object，在进程启动前建立归属，到时或中断关闭整个进程树。不要把 datagen 的 `--budget-hours` 当成停止机制。

超时退出码为 124，中断为 130，其他失败保留非零状态。预算运行器的 `run.json` 必须为 `complete: true`，其子报告也必须完整，才能使用结果；例如被杀死的 datagen 分片或未跑满的门控不能当成完整数据/验收。诊断曲线会周期性保存，超时后可用作部分进展，但不能声明训练完成。

运行器互斥锁拒绝同一预算的并发任务。若终端/运行器被强制关闭，锁和整段时间预留可能保留：先确认没有相关进程仍运行，再人工处理锁；账本保留预留耗时，不通过新建/重置预算来绕过上限。完整性来源于运行器状态，而不是旧的、可能尚未刷新的子报告。

## 阶段 1：现有训练原模型到量化导出的保真度

实现期间已做一次 45 秒硬限的短检查，实际约 3.1 秒；本地结果位于：

- `data/m5/reference_fidelity_v2/report.json`
- `data/m5/reference_fidelity_v2_run/run.json`

该检查从原 checkpoint 的 train_args 重建按对局划分，64 个训练侧校准样本与 64 个验证侧评估样本分开，常数预测用整个训练划分拟合。记录原数据 SHA-256、记录索引、对局编号和 checkpoint 身份，并尊重原训练的 `--limit`。**历史 checkpoint 未保存训练时的数据 SHA-256，本次显式使用 `--allow-unverified-data`，报告把划分独立性标为未验证**：当前文件与训练时是否完全相同无法追溯证明。它也不是全新、从未用于训练选择的测试集，不能代替正式棋力验收。首次检查的旧目录保留为历史记录，后续以 v2 报告为准。

新训练 checkpoint 自动保存训练数据 SHA-256，fidelity 核对不符会拒绝运行；缺少原始 seed/val_fraction 时也拒绝猜测划分。历史 checkpoint 的显式兼容选项只允许生成带限制说明的诊断，不会把数据身份提升为已验证。

同一评估集合上，原训练模型 vs 未校准整数 MAE 28.16208；vs **重新用训练侧样本校准**的最终整数 MAE 12.21901。STE 与整数参考 64/64 一致，C++ scalar/AVX2 与最终整数逐位一致。训练原模型 MSE 0.72066，训练集拟合常数的评估 MSE 0.75074，误差比值 0.95994；重新校准导出的比值为 0.97341。这些是当前 64 个样本的诊断，不能断言容量不足。

这里的 `candidate.nnue` 是诊断中重新导出的模型，**不是原 `nnue_v1.nnue`，也没有通过晋级门控**。原 checkpoint 和部署权重均保留。

如需复核，使用新的输出目录和同一预算：

```powershell
.venv\Scripts\python.exe tools\budget_run.py --ledger data\m5\budget.json --seconds 45 --out-dir data\m5\fidelity_repeat_run -- .venv\Scripts\python.exe trainer\diagnose.py fidelity --data data\raw\bench-d4\train.binpack --checkpoint weights\nnue_v1.pt --allow-unverified-data --probe build\engine\Release\nnue_probe.exe --samples 64 --out-dir data\m5\fidelity_repeat
```

报告将 `original_vs_raw`、`original_vs_final` 的搜索分误差、tanh 目标空间误差、各模型 MSE/CE、训练侧类别先验基线和 C++ 算术对齐分别列出。带训练专用 bias 的 CE 与无 bias 的 CE 分开，不暗示该 bias 被导出。

## 阶段 2：下一项需要用户运行的小样本拟合

以下任务设置 600 秒上限；实际耗时计入同一账本。固定 64 条记录、seed、无 D4 增广，float 和 STE 从相同初始化分别训练，保存同样本曲线、梯度范数、浮点激活裁剪统计和最终 checkpoint。它不使用验证集挑选 checkpoint，也不声称泛化。

```powershell
.venv\Scripts\python.exe tools\budget_run.py --ledger data\m5\budget.json --seconds 600 --out-dir data\m5\overfit_run -- .venv\Scripts\python.exe trainer\diagnose.py overfit --data data\raw\bench-d4\train.binpack --out-dir data\m5\overfit --samples 64 --steps 1000 --log-every 50 --seed 20261106 --device auto
```

跑完让 agent 读取 `data/m5/overfit/report.json`、`data/m5/overfit_run/run.json` 与两份 `*_curve.json`。同样本拟合 checkpoint 标为 diagnostic_only，不允许将其冒充具有独立验证划分的模型运行 fidelity。

判断顺序：浮点能否拟合 → STE 是否明显退化 → 是否存在持续裁剪或无效梯度 → 再决定优化、量化或目标的对照实验。数据覆盖与网络容量仍是待检验解释，不预先扩网。

## 后续分支：独立数据

只有读取前两阶段后才决定是否执行。若需要，使用新 seed 和新目录；例如以下命令准备新的 depth-4 RNG 流，1,800 秒上限仅是保护，不保证产出特定条数：

```powershell
.venv\Scripts\python.exe tools\budget_run.py --ledger data\m5\budget.json --seconds 1800 --out-dir data\m5\fresh_data_run -- .venv\Scripts\python.exe tools\datagen.py run --workers 28 --games-per-worker 20 --depth 4 --seed 20261107 --out-dir data\raw --tag m5_fresh --merge
```

完整完成后先 validate/verify 并审查 manifest；超时的批次不能作为完整训练集。不得直接复用同 seed/配置的校准分片当作新数据。比较模型时冻结相同的评估对局和标签变换，旧验证对局不能混入新增训练集；决定具体数据量/混合方式后再准备训练对照命令，避免先换数据划分再比较损失。原始文件、seed、训练/验证对局身份和 SHA-256 都应保留。

## 正式 M5 门控准备

冻结 100 个不同的随机开局，之后每个开局交换引擎颜色，共 200 局。该集合独立于训练生成流程，不根据比赛结果筛选，不反复调参迎合这个集合。

交付时已执行下列冻结命令，文件已存在，无需重跑；如仅复核可直接读取。重新生成到同一路径会拒绝覆盖。

```powershell
.venv\Scripts\python.exe tools\match_runner.py --games 200 --paired-openings --seed 20261109 --freeze-openings data\m5\formal_openings.json
```

在证据支持选出候选权重后，替换下例的 `weights\selected_candidate.nnue`。正式对打由用户运行；4,000 秒上限只有剩余预算足够时才能启动。预算不够则先报告已有结果，不能自动增加预算。此处不是让用户现在运行的连续流水线。

```powershell
.venv\Scripts\python.exe tools\budget_run.py --ledger data\m5\budget.json --seconds 4000 --out-dir data\m5\formal_gate_run -- .venv\Scripts\python.exe tools\match_runner.py --m5-gate --games 200 --seed 20261109 --openings data\m5\formal_openings.json --engine-a ".\build\engine\Release\gomoku_nnue.exe --depth 2 --nnue weights\selected_candidate.nnue" --engine-b ".\build\engine\Release\gomoku_nnue.exe --depth 2" --output data\m5\formal_gate.json
```

正式模式要求同一 exe、Renju、depth 2、VCF 开启、默认 64MB TT，仅评估器不同，完整对局。每局查询实际 ABOUT，NNUE 失效回退或后端不符会使比赛无效。报告记录 exe/权重 SHA-256、源码版本/工作区状态、开局文件 SHA-256、完整开局和每局着法；若比赛期间模型/引擎文件改变也视为无效。

正式模式用原始计数判断 `(wins + 0.5*draws)/200 > 0.65`；130 胜/70 负失败，131 胜/69 负通过。普通工具模式仍默认保留既有 >= 门控，可用 `--strict-gate` 显式切换。小批量诊断成绩、工具测试通过、导出对齐均不表示 M5 完成；更深搜索、限时棋力与外部对手另行验收。
