# 08: 历史版本测评与晋级

**What to build:** 用户选择候选模型和冻结历史版本后，可以在客户端发起公平对战、查看可信报告，并在候选通过预定条件时更新正式版本；失败保持当前正式版本。

**Blocked by:** 07 — 使用新模型实际对弈。

**Status:** ready-for-agent

- [ ] 没有正式版本时，经过数值检查和合法对局验证的首个新模型可登记为 v0；登记不伪称已战胜历史版本，避免初始版本建立死锁。
- [ ] 测评开始前冻结候选、对手、引擎、规则、开局和资源身份，核验实际使用的模型，拒绝意外回退或身份不符。
- [ ] 同一开局交换黑白，双方使用相同思考时间和线程资源；测试开局与候选训练隔离。
- [ ] 使用共用权威执行器裁判，完整检查黑方禁手和非法操作；保存对局序列及异常。
- [ ] 在开赛前固定有效局数或停止规则、得分率门槛、统计判断和异常处理，并提供有说明的默认方案；不沿用旧 M5 的固定门槛。
- [ ] 报告胜、和、负、严格胜率、得分率、有效对局数、区间或预定统计结论、用时和异常，考虑配对开局相关性。
- [ ] 崩溃、超时、非法着法和模型加载失败明确分类；规则判负与有效棋力证据区分，异常不能制造晋级。
- [ ] 通过后记录来源并切换正式版本；失败、中断、配置不符或证据不足时均保留原正式版本。
- [ ] 模型和报告可追溯，支持当前正式版本及选定历史版本的挑战；没有与 Rapfi 对战要求。
- [ ] 用真实小规模对局展示完整测评路径，并验证通过、失败、未完成和异常分支；小样本不足时正确报告不能判定。

## Verification

在对战 runner 与正式版本发布边界验证冻结、公平资源、身份、统计输出及晋级决策。评测配置在看到结果前确定，不为获得通过而修改门槛。
