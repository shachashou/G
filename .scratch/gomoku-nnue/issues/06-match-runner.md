工单 06 完成，验收记录：

- **裁判模型**：`tools/match_runner.py` 自己持有权威 15×15 棋盘；每步用 Gomocup `BOARD` 全量同步到待走方引擎，再读取 `x,y` 回复。两个引擎不共享增量状态，因此任意两版 build（含未来 NNUE 版）都可直接对打。每局独立启动两个进程，开局发送 `START 15` + `INFO rule 1|2`（可选 `INFO timeout_turn`）。
- **规则判定**：Python 侧实现五连优先、Renju 黑需恰好五连、黑长连判非法、白/freestyle 五连及以上胜；三三/四四禁手仍由各引擎的 `Board::isPlayable` 过滤，刻意不在 Python 里复制一套规则，避免引入新的跨语言契约接缝。
- **配置**：`--engine-a/-b`（Windows 友好命令串，可带 `--depth`/`--movetime`/`--random`/`--no-vcf`）、`--games`、`--rule`、`--opening-plies`（0..8）、`--opening-region`（默认中心 7×7）、`--seed`、`--move-timeout`、`--timeout-turn`、`--max-plies`。开局随机手数上限 8 的依据：≤4 个黑子时 Renju 长连/四四/三三禁手在数学上不可能出现，随机开局必然合法。按局号奇偶交替先后手，`--seed` 保证可复现。
- **异常与结果**：超时、进程崩溃/stdout 关闭、坏回复（`ERROR`/`UNKNOWN`）、越界/占用点、Renju 黑长连，一律记为该方失败并写入 anomaly（`kind`/`engine`/`ply`/`detail`）。`--output` 的 JSON 含 config、summary（W/D/L、win_rate、decisive_win_rate、异常计数）与每局完整着法序列（含随机开局标记与走子方归属），可离线复查。`--min-win-rate` 用 score rate `(wins + 0.5*draws)/games` 做门控，不达标退出码 2，供 M5（>65%）与 M6 自举轮次直接使用。
- **自检**：`engine/tests/match_runner_tests.py` 接入 CTest。覆盖裁判规则单测（黑恰好五/黑长连禁手/白长连胜/freestyle）、Windows 命令串解析、随机开局可复现且限中心 7×7；**04 风格 `--depth 2` 引擎对 02 随机基线 4 局交替先手 4/4 全胜**（`--min-win-rate 1.0` 门控通过）；freestyle `rule 1` 双引擎对局；门控失败退出码 2；以及用临时假引擎确定性地复现非法着法 / 超时 / 崩溃三种异常计负。
- **CTest**：7/7 通过（新增 `match_runner_tests`，TIMEOUT 120 秒兜底；实测整套仍为秒级）；引擎版本升至 0.6.0（工具链发布，C++ 引擎逻辑未改）。
