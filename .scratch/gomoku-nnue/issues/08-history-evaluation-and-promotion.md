# 08: 历史版本测评与晋级

**What to build:** 用户选择候选模型和冻结历史版本后，可以在客户端发起公平对战、查看可信报告，并在候选通过预定条件时更新正式版本；失败保持当前正式版本。

**Blocked by:** 07 — 使用新模型实际对弈。

**Status:** done

- [x] 没有正式版本时，经过数值检查和合法对局验证的首个新模型可登记为 v0；登记不伪称已战胜历史版本，避免初始版本建立死锁。
- [x] 测评开始前冻结候选、对手、引擎、规则、开局和资源身份，核验实际使用的模型，拒绝意外回退或身份不符。
- [x] 同一开局交换黑白，双方使用相同思考时间和线程资源；测试开局与候选训练隔离。
- [x] 使用共用权威执行器裁判，完整检查黑方禁手和非法操作；保存对局序列及异常。
- [x] 在开赛前固定有效局数或停止规则、得分率门槛、统计判断和异常处理，并提供有说明的默认方案；不沿用旧 M5 的固定门槛。
- [x] 报告胜、和、负、严格胜率、得分率、有效对局数、区间或预定统计结论、用时和异常，考虑配对开局相关性。
- [x] 崩溃、超时、非法着法和模型加载失败明确分类；规则判负与有效棋力证据区分，异常不能制造晋级。
- [x] 通过后记录来源并切换正式版本；失败、中断、配置不符或证据不足时均保留原正式版本。
- [x] 模型和报告可追溯，支持当前正式版本及选定历史版本的挑战；没有与 Rapfi 对战要求。
- [x] 用真实小规模对局展示完整测评路径，并验证通过、失败、未完成和异常分支；小样本不足时正确报告不能判定。

## Verification

在对战 runner 与正式版本发布边界验证冻结、公平资源、身份、统计输出及晋级决策。评测配置在看到结果前确定，不为获得通过而修改门槛。

### 实施与验收记录（2026-11-10）

**后端与冻结**

- `tools/history_evaluation.py` 提供 GUI / CLI 共用的 `evaluate()`。复用旧 runner 的 Gomocup 传输，比赛规则仅由 `ExecutorClient` 对接的 C++ 权威执行器判定。
- 开赛前复制引擎、候选、历史对手、数值报告和训练清单，落盘 `manifest.json`：SHA-256、模型 id、规则、开局、时间、线程、VCF、统计方法、异常策略、固定局数及实现文件身份。双方核验 ABOUT 的实际模型、架构、规则、特征、价值契约和 GMVALUE1 评估方式，不接受回退。
- 以同一开局换色两局，同一引擎、相同时间、单线程；总回复截止点不因 MESSAGE 重置，中断及时回收进程。
- 导出新增由模型元数据 SHA-256 绑定的 `training_positions.json`；开局排除候选训练/验证数据的 D4 等价局面，以及同一测评目录中已经用过的开局。续训 checkpoint 累计保留已用清单，换池/淘汰不会抹掉历史；缺少清单的旧 checkpoint 明确拒绝续训。
- 数值检查复核报告对应的模型哈希和固定容差；评测不调用 Rapfi、不写训练样本池，标记 `purpose=evaluation-only`。

**统计默认方案**

- 每个对手默认 64 对、128 局，至少 32 个完整开局对；固定赛程，不提前因暂时领先宣布成功。
- 每对两局平均得分为一个 [0,1] 观测，避免将同开局两局当作独立观测。对 K 个冻结对手采用 Bonferroni 校正的 Hoeffding 单侧下界：`max(0, paired_mean - sqrt(log(K/alpha)/(2*n_pairs)))`，默认 `alpha=0.05`。
- 所有对手下界都严格高于赛前得分率基线（默认 0.5）才具备晋级资格；报告区分样本不足、证据不足、未过基线与赛程不完整。保守界可能需要更多对局，不因结果临时修改方法。
- 报告胜/和/负、严格胜率、得分率、完整开局对、有效局数、单侧上下界、用时和异常。崩溃、超时、非法着法、身份不符或模型加载失败终止测评；规则判负单列且不计棋力证据。手数截断是未完成，不伪造和棋。

**登记与发布**

- `tools/model_registry.py` 保存 `weights/registry` 正式历史。没有正式版本时，数值检查和一对完整合法自对弈通过后可登记 v0，来源 `initial-validated`，明确不是历史棋力胜出。
- 挑战自动包含当前正式版本，可额外选择历史版本。发布前复核封存配置/报告哈希、模型身份、统计条件，以及权威执行器重放的完整终局、胜负与配对记录。
- 发布带锁、比较赛前现任版本并原子替换 `state.json`；现任变化、篡改、配置不符、异常、未完成或证据不足均保留原版本。每版保留模型、数值报告、训练清单、测评配置与报告，记录上版和来源。
- `report.json` 是封存证据，`result.json` 是发布回执；写回执不反过来修改封存报告。

**客户端**

- 新增可滚动的「历史版本测评与晋级」面板：候选浏览、历史对手多选、对数/时间/基线、v0 验证登记、挑战晋级、停止、已有报告查看与使用当前正式版本。
- 后台运行，赛前捕获配置；运行中禁止切换模型/对局或启动其它任务。显示有效局数、胜和负、严格胜率、得分率、配对下界、结论、异常、用时与报告路径。
- `play.bat` 默认加载登记表当前正式模型，`--model` 可显式试玩候选。模型状态区分候选、正式版本与冻结历史；没有正式版本时明确显示手工评估。

**测试与真实演示**

- `history_evaluation_tests` 覆盖真实引擎 v0 对局和小样本挑战；受控对手在真实 C++ 裁判下覆盖通过、失败、多对手校正、保留原版本、截断、中断、身份拒绝、配置篡改、源文件更新后快照不变、数值/清单拒绝、三三/四四判罚、总回复超时和续训清单合并。受控胜出是分支测试，不是棋力证据。
- `gui_history_smoke` 覆盖真实窗口登记 v0、后台历史挑战、小样本不足不晋级、停止、真实版本身份与新窗口默认加载正式模型。
- 全量 CTest **33/33 通过，无跳过**；最后调整界面后台导入后，两项相关 GUI 测试再次通过；`git diff --check` 通过。
- 旧 `gui_collect_smoke` 使用时间种子，回归时出现所有样本被过滤的随机失败；固定种子 1 并隔离临时样本池后通过，未放宽过滤或样本断言。

- 未向生产 `weights/registry` 登记验收模型。生产默认对手仍需用户选择候选并登记 v0；演示仅验证链路与拒绝过度结论，不证明棋力提升。
