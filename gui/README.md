# 桌面对弈客户端（工单 02 / 13 / 14）

Windows 本地客户端：选择执黑或执白，与现有引擎完成一局有禁手五子棋，查看合法落点、禁手原因、着法记录、对局结果与重放校验，并可随时开新局。界面按“像手机应用一样简单有效”的原则组织：棋盘是视觉焦点，右侧只显示当前模式的主操作和一行状态，复杂参数进入右侧设置 sheet。

## 视觉与信息层级（工单 13 / 14）

- **主题**：浅暖中性背景、白色卡片、轻边框/投影、14–20px 圆角、单一 `#007AFF` 强调色、`#FF3B30` 危险色；字体优先 Segoe UI Variable / SF Pro Text / Segoe UI / Microsoft YaHei UI。
- **可调尺寸**：窗口可自由拖动缩放；棋盘始终按窗口大小等比重绘（15×15 网格居中、棋子/落点/禁手标记随格距缩放），不会被拉伸或裁切。首次启动约为屏幕的 48%（上限 900×560），之后沿用上次关闭时的大小；最小 700×420。字距与圆角固定，只有棋盘和右侧面板随窗口伸缩。
- **顶部**：大标题“五子棋”与一行说明；右侧是模型胶囊、隐藏棋盘、设置按钮和身份 pill。点击胶囊选中模型立即应用；忙时拒绝并说明原因。
- **模型胶囊**：显示短标签 `正式 vN` / `历史 vN` / `候选 · <目录>` / `候选 · <任务 id8>/round-N`，按正式、历史、候选的顺序排列；完整路径和模型 id 在悬停提示与设置面板里，下拉弹层按最长标签自适应宽度。
- **模式**：三个主标签“对弈 / 训练 / 测评”；训练页内部三段“采集数据 / 从0训练 / 自我训练”，当前模式只显示一个主操作卡。
- **棋盘**：白色圆角卡片 + 轻投影；暖色棋盘、低对比网格、轻投影棋子、较小的蓝色合法落点、蓝色最后一手圆环。后台任务运行时棋盘可切换为只读实时镜像，带 `LIVE`/暂停/训练横幅。
- **隐藏棋盘**：顶部「隐藏棋盘」按钮（或 `Ctrl+B`）收起棋盘卡片，右侧面板占满窗口；按钮随即变为「显示棋盘」。隐藏只是显示偏好，对局、实时镜像与后台任务照常运行，LIVE/返回对局入口暂时不显示；重新显示时按当前状态重绘。选择跨启动保留。
- **状态**：标题下只有一行活动状态 + 内联错误；完整指标、日志、报告和技术详情进入设置 sheet。
- **设置 sheet**：右侧滑出 + 半透明遮罩，分组“模型 / 高级对局设置 / 对局详情 / 教师打标 / 采集参数 / 从0训练参数 / 任务与资源 / 恢复未完成任务 / 任务指标 / 测评参数与对手 / 测评报告”；“模型”分组里还有「清理模型与数据…」（候选模型 / 历史数据两页）；关闭按钮、遮罩或 ESC 收起，后台任务继续运行。
- **保留**：所有模型选择、教师打标、VCF、训练、采集、任务恢复和测评控件仍在；只是移动位置或默认隐藏，不删除功能。

## 框架与本地控制方案

- **GUI 框架：PySide6 6.9.3**（Qt for Python）。控件与信号槽完整，适合后台任务与长时间运行；与 `trainer/` 和 `tools/` 同为 Python，后续采集、自我训练、测评工单可以直接复用同一套后端客户端。依赖已写入根目录 `requirements.txt`，离线可运行。
- **控制协议：JSON-lines over stdin/stdout**。GUI 通过 `tools/executor.py` 启动 `gomoku_nnue.exe --executor`，每行一个 JSON 请求、一行一个 JSON 响应。原 Gomocup 协议保持不变，仍供引擎对引擎对战使用。
- **权威执行器**：所有规则（完整合法落点、禁手原因、落子结果、终局）只由 C++ `Executor` 给出。GUI 和 Python 客户端不实现任何禁手或胜负算法。

| 命令 | 作用 |
|---|---|
| `about` | 引擎身份、实际评估方式及新模型的模型 id/架构/规则/特征/价值契约；手工评估不会标成已训练 NNUE |
| `new_game` | 15×15、黑先白后、自由开局的新局 |
| `state` | 棋盘、行棋方、结果、规则、着法历史快照 |
| `legal_moves` | **完整**合法落点集合，以及每个禁手点的具体原因 |
| `move_reason` | 单点合法性及拒绝原因 |
| `play` | 落子；非法请求或终局后落子不改变棋盘、行棋方或历史 |
| `undo` | 撤销上一手 |
| `rebuild` | 局面重建与校验（拒绝损坏输入；报告是否与黑先行棋一致） |
| `replay` | 从空棋盘重放着法序列，得到一致终局 |
| `candidates` | 搜索候选裁剪，明确区别于完整合法落点集合 |
| `vcf` | 对当前局面做一次开源 VCF 算杀查询：状态、首着、变化、结束证据、预算与实际开销 |
| `think` | 引擎选点（只返回着法，不落子），GUI 再显式 `play`；结果附带本轮算杀状态与调用点 |
| `quit` | 结束执行器进程 |

## 行为约定

- 引擎思考放在后台线程，主线程只负责界面；思考期间不向执行器发其它请求，界面仍可响应「新局」「停止对局」和关闭窗口。
- 「停止对局」和关闭窗口会终止引擎子进程并按需重建，不留下后台工作进程；引擎侧诊断与协议错误在状态区明确显示。
- 顶部模型胶囊列出 `weights/` 下的 `*.gmvalue`、手工评估和“浏览模型文件…”；选中即启动带 `--value-model` 的新引擎进程并开始新局。界面显示实际加载的模型 id、架构、规则/特征/价值契约与候选/正式/历史身份，加载失败时保留当前可用的引擎进程并明确报错，绝不把失败模型显示为已加载。
- 没有模型时显示「手工威胁评估（没有加载已训练模型）」；加载旧版 NNUE 时显示后端与权重路径。手工评估不会被标记为已训练 NNUE。
- 双击 `play.bat` 默认加载 `weights/registry/state.json` 中的当前正式版本；`--model` 显式选择候选。模型面板区分候选、当前正式版本和冻结历史版本，哈希校验失败时明确报告。
- 设置面板「模型」分组的「清理模型与数据…」打开清理对话框，两页共用同一套保护：候选模型页按任务分组列出候选包与大小，默认勾选可安全清理的旧轮；历史数据页列出任务目录与测评记录，已完成/失败任务默认勾选，运行中任务、登记版本引用的测评记录永不勾选，可恢复任务默认不勾。删除前二次确认，任务运行中拒绝打开；删除只作用于对应根目录内的整目录，登记表不参与扫描。
- 测评页选择候选，设置中的「测评参数与对手」可选择额外历史对手，当前正式版本自动参与挑战；可设置开局对数、双方相同的每步时间和得分率基线。数值检查和一对合法完整对局通过后可登记 v0；后续只有所有对手均通过冻结的统计门槛才原子晋级。可查看胜和负、得分率、严格胜率、有效局数、配对下界、异常和报告路径；证据不足、失败或停止时均保留原正式版本。详见[根目录说明](../README.md#历史版本测评与晋级工单-08)。
- 顶部胶囊切到正式/历史版本时，测评候选框会留空而不是填入该版本；候选与任何已登记版本是同一个文件时，启动前用中文拒绝，不创建空测评目录。保留现任时报告的「判定」会写出得分率、配对下界与门槛，并提示增加开局对数或继续训练。
- 测评参数与训练任务设置里实时显示「晋级条件」：按当前开局对数、对手数和基线换算出需要的配对得分率（例如 64 对 / 单对手 = 65.3%，128 对 = 60.8%）。把基线调高只会让所需得分率更高——门槛看的是置信下界，不是原始胜率。
- 测评在后台运行，界面可滚动查看各面板；「停止测评」保存部分报告并结束比赛进程。测评期间不允许切换对局、模型或开始其它任务。
- 一局结束后自动用同一执行器重放着法序列并显示校验结果。
- 状态区显示算杀引擎身份（`quintet@commit`）；「算杀检查（VCF）」按钮在后台线程查询当前局面，显示已证明/未证明/预算耗尽/中断、首着、变化、预算与实际开销；查询期间界面保持响应，「停止对局」会终止引擎进程，结果按未知处理。
- 引擎每步的 `think` 响应也会带上本轮算杀状态：`proven` 且首着合法时引擎直接走该着法，其余状态不改变正常评估。
- 每次 AI 行棋后，「对局详情」与活动状态行显示实际搜索深度（层 = 半手，默认上限 8 层 = 双方各 4 手）、节点数与评分；着法来自算杀时注明。中盘 1000 ms 实测约 6 层。
- 后台采集/自我训练/测评每一手会发出只读 `cells` 快照；棋盘实时镜像其中一盘（`LIVE`、模式/编号、行棋方、手数）。多 worker 固定跟随一盘，2 秒内不混盘；暂停冻结并淡化，训练阶段保留终局 +「训练中」，停止约 1.2 秒后回到玩家棋盘。
- 玩家不在进行中的对局时自动显示后台棋盘；玩家正在下自己的棋时保留玩家棋盘，只显示 `LIVE` 按钮；切换后按钮变为「返回对局」。实时棋盘不能落子，不改变权威对局或任务状态。
- 隐藏棋盘后不显示 `LIVE`/「返回对局」，状态行提示「后台任务运行中」或「棋盘已隐藏（Ctrl+B 显示）」；后台镜像仍在更新，重新显示时按当前状态重绘。隐藏选择保存在客户端设置中，下次启动沿用。
- 实时快照只走 GUI 队列/信号，不写入 `state.json`、任务事件、测评报告或样本池。
- 训练页「采集数据」段选择局数与容量、设定教师预算后启动后台采集，实时显示生成/有效/入池/池容量/有效每秒与过滤原因；「停止采集」让当前对局中止并被丢弃，不遗留采集或教师进程。
- 训练页「从0训练」段在设置中选择样本池、步数/批大小/学习率/损失，后台训练并显示训练/验证损失、验证 MAE、导出保真度和模型路径；「停止训练」保存 checkpoint 并导出当前模型，关闭窗口会先停止训练线程。
- 右侧统一为「对弈」「训练」「测评」三个标签；训练页内部切换「采集数据 / 从0训练 / 自我训练」，模型胶囊始终显示同一个实际加载的模型与正式/候选身份。
- 训练页「自我训练」段一次启动采集、教师打标、候选训练与历史测评，可配置启动/新增样本量、容量、每轮训练预算、设备和结束条件。采集与训练并行；晋级只影响下一盘采集。界面显示阶段、池累计计数、吞吐、采集模型、训练/验证指标、资源及测评结论。停止或关闭窗口会保留已提交数据和正式模型，并等待所启动进程退出；操作与默认值见[根目录说明](../README.md#持续教师训练工单-09)。
- 任务参数是所见即所得：最多采集局、轮数、步数、学习率、样本量、并发、开局对数、自对弈时间与探索率、输出目录、设备与模式，改动立即生效并在 300 ms 后自动保存（关闭窗口也会落盘），重开窗口沿用；没有「保存」按钮，不会被默认值或预设悄悄覆盖。任务运行中参数锁定，改动只影响下一个新任务。最近一轮若因导出保真度失败被丢弃，状态行与任务指标会写明 `p95` 实测值与容差。
- 该面板可显式选择教师训练、自主过渡或完全无教师。自主模式需要已有正式版本；过渡允许按权重使用历史教师样本，完全无教师同时排除训练/验证的教师标签。新增自对弈时间、探索概率和历史教师权重控件；界面说明所选模式、实际来源与总池/可用容量。教师不可用时自主任务仍可启动，停止后不会静默切回教师。
- 自我训练任务提供「暂停任务」「继续暂停的任务」「停止任务」。暂停在安全边界生效，状态行区分暂停中/已暂停/恢复中/已停止；暂停期间不结束工作线程，继续后从当前棋局、优化步检查点或未完测评继续。关闭窗口会先停止并等待线程与子进程退出。
- 重启客户端后，面板扫描任务输出目录，把未完成/已暂停/已停止的任务放入「恢复已中断任务」。选择后先核验冻结配置、引擎副本、检查点和样本身份，再从原任务目录继续；配置不符或文件损坏会明确拒绝。已发布的候选不会重复晋级。详见[根目录说明](../README.md#任务暂停恢复与重启工单-12)。
- 「采集数据」的暂停在整盘棋之间生效；「从0训练」的暂停在优化步边界保存 `last.pt`，可点「继续上次训练」；「测评」的暂停会丢弃未完成配对，恢复时按原冻结开局整对重做。
- 尚无正式模型时，自主模式在启动前提示先建立 v0，不创建失败任务；点击「先建立 v0：切换到教师训练」只切换选择，再点击「启动教师训练任务」。等正式版本显示 v0，停止并等待任务结束后，才切回自主模式启动。已有合格候选也可用历史测评面板「验证并登记 v0」。
- 自我训练默认使用本机高吞吐预设：32 逻辑线程时 24 路采集、8 路测评、PyTorch CPU 4 线程、GPU 批 2048，首次训练需要 2048 条训练样本；「少量数据快速启动」恢复单路 / 批 32。界面可调整并发、训练快照、待训练积压和验证对局。修改只影响新任务。
- 默认状态 / 测评报告每 2 秒合并写盘，周期检查点至少间隔 60 秒，停止与最终结果立即保存；最佳 checkpoint 在内存中冻结后落盘。状态 / 检查点间隔在面板可调，详见[并发与磁盘写入](../README.md#并发与磁盘写入)。
- 状态区显示本地 Rapfi 教师的身份与安装状态（版本、Renju 权重、标签版本）。「打标并保存样本」在后台线程用独立执行器校验当前局面、跑 VCF 过滤、调用教师并把结果写入 `data/teacher/samples.sqlite3`，面板显示原始评分、归一化价值、过滤原因、教师状态、预算与有效样本数；教师缺失或哈希不符时明确报错，绝不产生假标签。

## 启动

先按根目录 `README.md` 用 venv 的 cmake + Ninja 构建出 `build/engine/gomoku_nnue.exe`，然后任选一种：

~~~text
双击 gui\play.bat
.venv\Scripts\python.exe gui\gomoku_gui.py
.venv\Scripts\python.exe gui\gomoku_gui.py --engine build\engine\gomoku_nnue.exe --movetime 800
.venv\Scripts\python.exe gui\gomoku_gui.py --engine build\engine\gomoku_nnue.exe --model weights\value-demo\model.gmvalue
~~~

也可用环境变量 `GOMOKU_ENGINE` 指定引擎路径。

`--pool PATH` 指定采集与训练的默认样本池，`--collection-seed N` 固定采集输入以复现问题；默认种子随启动任务变化。
