# 03: 接入开源 VCF

**What to build:** 用户对弈时实际使用支持禁手规则的开源 VCF；已证明的战术结果可以影响引擎选点，并能从客户端检查首着、变化或证据及搜索状态，同一能力可供后续数据筛选复用。

**Blocked by:** 02 — GUI 完成一局合法对弈。

**Status:** ready-for-agent

- [ ] 选择实际可接入且支持 Renju 的开源实现，记录来源、固定版本、许可证、必要依赖和接入方式；不预设 Rapfi 提供独立 VCF 库。
- [ ] 新方案的正式算杀路径复用上游实现，不继续使用自研 VCF 充当交付结果，也不另写算杀算法替代上游。
- [ ] 适配接口区分已证明结果、预算内未找到证明、预算耗尽或中断以及输入错误；记录预算、首着和可复核的变化或证据。
- [ ] 战术证据中的落点经过权威执行器合法性复查，并覆盖涉及黑方禁手的攻击与防守。
- [ ] 只有已证明结果可覆盖正常价值判断；未找到 VCF 不被解释为没有其他强制胜法。
- [ ] 在真实搜索与 GUI 中接通状态和结果；演示确定杀棋、合法防守、未知及停止场景。
- [ ] 节点或时间限额可配置，实际达到限额时不返回伪造的确定结论；记录所选调用位置和开销。
- [ ] 战术适配能力可由数据打标流程直接复用，不依赖 GUI 状态或教师评分字符串。

## Verification

在公开适配边界使用确定性战术题和真实上游实现验证结果、合法性、限额与中断。至少一条真实引擎对局路径证明开源实现已被调用。
