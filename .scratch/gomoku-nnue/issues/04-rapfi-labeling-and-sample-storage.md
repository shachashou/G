# 04: 教师评分与有效样本落盘

**What to build:** 用户在客户端提交合法局面后，能够由本地 Rapfi 评分，看到战术筛选和异常原因，并保存一条可追溯、可被后续训练读取的有效样本。

**Blocked by:** 03 — 接入开源 VCF。

**Status:** ready-for-agent

- [ ] 实际启动本地 Rapfi 教师，核验其可执行文件、权重和 Renju 配置，记录版本身份、搜索预算及完成同步方式。
- [ ] 选择并验证可用的局面评分方法；不把引擎建议着法、静态评分和搜索评分混为同一契约。
- [ ] 原始评分、原始视角、归一化方法与参数、转换后的价值和标签版本可追溯，明确供后续网络与搜索共用的价值约定。
- [ ] 使用权威执行器校验输入，调用共用战术适配器，排除终局、已识别算杀、mate 标签和异常响应。
- [ ] 超时、中断、预算耗尽等未知情况单独计数，默认不进入教师训练队列；有限 VCF 筛选不宣称证明不存在其他杀棋。
- [ ] 保存盘面、规则、行棋方、对局或独立采样来源身份、着法信息、采集模型身份、标签来源与版本、战术状态及可空的最终结果；缺失字段有明确语义。
- [ ] 独立采样局面和未完成对局没有真实结果时，不补写和棋；教师标签与最终胜负可以分别存在。
- [ ] 明确数据格式版本与完整性规则，读回后内容一致；损坏、截断、错误规则或不兼容版本明确拒绝。
- [ ] GUI 展示原始请求状态、评分结果、过滤原因及有效样本数；依赖缺失时明确失败，不伪造标签。

## Verification

在客户端、真实教师进程和样本读写边界完成小批量闭环；验证黑白视角、已知终局、战术命中、超时与损坏数据，兼顾可重放的适配契约检查。
