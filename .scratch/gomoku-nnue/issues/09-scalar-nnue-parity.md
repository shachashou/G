工单 09 完成，验收记录（`ctest` 13/13 全绿，整套 10.91 秒；引擎版本 `0.8.0`）：

- **权重加载（`engine/src/nnue.h/.cpp`）**：`NnueNetwork::load()` 一次性读入 `GMNNUE01` v1 文件，逐项校验魔数、版本、header_size、四个维度、QA/QB/score_scale/weight_clamp、保留位全零、body 长度、FNV-1a 校验和、int8 权重不越 `weight_clamp`。所有拒绝路径抛 `NnueError`，消息带文件路径与具体原因（如 `bad magic (expected GMNNUE01)` / `checksum mismatch` / `truncated header`）。显式按小端解析，不依赖宿主字节序。
- **标量前向**：`infer(sparse, stm)` 是完整稀疏参考路径，逐位复现 `trainer/weights_format.py::infer_int()`：`acc = clamp_i16(b0 + ΣW0)` → `ClippedReLU(0,QA)` → `L1` → `round_div(z,QA)+b1` → `ClippedReLU(0,QB)` → 双头按 stm 选择 → `round_div(y,QB)+b2`。`roundDiv()` 为半数远离零（不用 C++ 截断除法），累加在 int32/int64 中完成，只在消费累加器时做一次 int16 饱和。
- **搜索内增量路径（仍是标量、无 SIMD）**：`Evaluator` 持有 `NnueAccumulator`（int32[1024] 精确和，不做中间饱和），`init(board)` 全量重建、`update(board, move, to)` 在落子/撤子时差分加减对应 `W0` 行；`evaluate()` 只跑后段 1024×15。这样增量路径与全量稀疏路径**逐位一致**（C++ 测试在 10 步落子/撤子序列中每步对拍），同时避免每个叶子重算 225×1024。工单 10 只需把这段标量累加器换成 AVX2。
- **最小侵入接入**：`EngineConfig::nnueWeights` + CLI `--nnue PATH` → `Protocol` 构造时加载一次权重，`Search::setNetwork()` 借用指针，`findBestMove()` 里 `eval.setNetwork()`；不配 `--nnue` 时完全是原来的手工评估路径。`moveHeuristic()` 仍走手工威胁分，保证 datagen 开局采样与工单 07 的复盘校验确定性不变；TT、VCF、`kMate=1e6` 分数体系均不变（NNUE 输出是搜索分尺度，远小于 mate 分）。`ABOUT` 新增 `eval="nnue"|"handcrafted"` 便于外部观察后端。
- **容错与协议洁净**：权重缺失/损坏只在 **stderr** 报清晰错误并回退手工评估，绝不写 stdout（Gomocup 协议流）；黑盒测试验证坏魔数与缺失文件两种情况下 `START 15 -> OK`、仍能合法走子、进程退出码 0。
- **跨语言契约 ①（特征索引）**：`nnueSparseIndices(board)` 按 `cell = y*15+x`、黑 `0..224` / 白 `225..449` 产出升序集合；`nnue_probe features` 把 C++ 结果交给 Python 比对 `features.sparse_indices()`。24 个确定性合成局面 + 16 个真实 `data/raw/bench-d4/train.binpack` 采样局面，两组权重（手算小权重 / 训练区间随机权重）各跑 40 个局面，全部完全一致。
- **跨语言契约 ②（数值）**：`nnue_probe infer`（全量稀疏）与 `nnue_probe board`（增量累加器）在同样 40 个局面上与 `infer_int()` **逐位相等**；手算用例 `W0[112,0]=5, b0[0]=3, W1[0,0]=7, b1[0]=1` 得 stm0 `= 2`、stm1 `= 5`，与 `training_tests.py` 一致。torch 可用时用 `NNUEModel.from_quantized_weights()` 重建参照：`quantized=True` 的 STE 前向与 C++ 输出逐位一致；**真实 `weights/nnue_v1.nnue` 上 PyTorch 浮点前向 vs C++ 实测 `MAE 0.3273 / max 0.7367`，在 `export_report.json` 建议容差 `≤ 2` 内**（16 个真实 binpack 采样局面）。
- **完整对局**：两台 `--nnue ... --depth 1` 引擎自对弈自然结束（9 手黑胜），每步合法、双方干净退出；真实权重 `weights/nnue_v1.nnue` 也验证过 `START/ABOUT/TURN` 全链路（`eval="nnue"`，stderr 空）。
- **测试（`engine/CMakeLists.txt`）**：新增 C++ `nnue_tests`（格式拒绝 9 类、round_div、手算前向、int16 饱和、增量对拍）、Python `nnue_parity_tests.py`（跨语言 + torch）、`nnue_blackbox.py`（完整对局 + 回退）。Python 测试不依赖 gitignore 产物：自己用 `weights_format.pack_weights()` 生成确定性权重；真实权重/真实 binpack/torch 存在时自动追加正式验收，否则打印 SKIP。
