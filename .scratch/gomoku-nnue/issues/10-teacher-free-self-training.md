# 10: 完全无教师自主训练

**What to build:** 用户选择已有正式版本启动自主训练后，系统由完整自我对弈获得实际胜负，训练候选并挑战历史版本；完全无教师模式即使没有 Rapfi，也不再调用教师或抽取教师来源标签。

**Blocked by:** 09 — 持续教师训练闭环。

**Status:** done

- [x] 复用公共持续训练编排，以实际对局结果替换教师评分监督；运行时不依赖教师模式初始化成功或 Rapfi 已安装。
- [x] 自我对弈使用正式版本快照，按记录的探索策略产生多样合法对局；盘中不替换模型。
- [x] 只有按规则完成的对局才回填自然胜负，按同一价值视角转换为训练目标；崩溃、超时和人为截断不伪造为和棋或自然结果。
- [x] 可以排除不适合价值训练的战术局面，但保留整盘真实结果与来源；不把模型原始评分原样回灌作为自主监督。
- [x] 界面和运行记录区分停止新增教师标签的过渡模式与完全无教师模式；混合监督时记录尺度、权重及来源。
- [x] 完全无教师模式只抽取自主来源的有效监督，处理已有混合样本池时不暗中使用教师标签。
- [x] 阻断或移除 Rapfi 后，真实完成自我对弈、结果入池、候选训练、导出、数值检查和历史版本测评；日志与进程记录能够核验没有教师调用。
- [x] 候选失败或证据不足不替换正式版本；功能验收不要求每轮实际棋力提升。
- [x] 正式转向无教师训练的证据记录与相对历史版本的测评关联，不按固定样本数毕业，也不要求战胜 Rapfi。
- [x] 用户可停止自主训练，保留现任模型；需要时可显式切回教师训练，不静默恢复教师调用。

## Verification

在真实任务编排边界禁用教师并完成低预算自主闭环；验证监督来源、完整结果、黑白视角、异常隔离和候选失败保留现任版本。

### 实施与验收记录（2026-11-10）

**共享调度与明确模式**

- 继续使用 `TrainingTask` 的生产、训练、数值导出、历史测评、背压、保留与停止流程；新增 `SelfPlayDataSource` 替换监督来源。教师适配器改为仅在教师数据源内延迟导入，自主后端不初始化教师，不依赖 Rapfi 安装成功。
- `TaskConfig.mode` 明确为 `teacher`、`transition`、`selfplay`。过渡模式停止新增教师标签，允许历史教师样本；完全无教师模式训练和验证都只允许 `selfplay_result`。两种自主模式必须已有正式版本，缺失或中途丢失时明确失败，不退回手工对手或教师。
- 过渡标签统一到黑方 [-1,1] 价值空间，历史教师按行棋方符号转换，结果直接用黑方绝对胜负。默认每样本损失权重为教师 0.25、结果 1，可赛前配置；MSE / SmoothL1 均支持加权。模式、来源、数量、归一化、视角、范围与权重进入数据身份、checkpoint 和导出元数据。

**完整结果与规则**

- 新增 `tools/selfplay_data.py`。每盘绑定当前正式模型的 id / SHA-256 / 版本，核验实际 ABOUT 身份，盘内固定。复用可中断、有总回复超时的 Gomocup 传输，裁判与完整棋谱重放均走 C++ 权威执行器。
- 默认中心 7×7 随机开局 4 手，前 16 手以 0.1 概率从完整合法落点探索，其余由同一模型搜索；每步 30 ms，每盘最多 225 手/60 秒。所有配置、种子和每手来源写入 `games/*.json`。
- 只有自然终局且重放一致才提交结果：黑胜 +1、和棋 0、白胜 -1；行棋方不改变符号。所有普通模型评分字段为空，不把自己的估值回灌成监督。
- 截断/停止不提交结果；超时、崩溃、身份或非法着法异常使任务失败并保留现任。记录完整已走序列、异常和未完成状态，不伪造和棋；事件区分 `data_commit`、`data_incomplete`、`data_interrupted`。
- 默认排除采样点上已证明的 VCF；过滤位置与证据、完整对局和真实终局仍保留。有限搜索未知仅保留状态，不能宣称无算杀。pool run 绑定最终棋谱哈希。

**混合池隔离与数据提交**

- `SamplePool.read_batch()` / `training_snapshot()` 支持在抽样前用 SQL 筛选标签来源；按来源统计已提交训练增量，教师历史和暂存写入不会假装成新增结果样本。
- 新结果组可冻结自己的验证对局，保留既有教师验证成员；沿用全局 D4 规范形，跨组泄漏也会拒绝或按既定池规则处理。完全无教师的训练/验证快照都仅含结果监督，面板分别显示总池容量与当前模式可用数量。
- 自主模式默认至少从 2 盘训练对局混合取样，且样本数/新提交数量达标；背压在这些门槛可用后才生效，避免未攒齐多盘数据就停产。次数、时间、积压与磁盘控制继续使用工单 09 配置。
- SQL 提交和完整性检查拒绝没有终局或与游戏最终胜负不一致的结果标签。旧教师样本保留，用户无需清空已有池。

**客户端与教师退出证据**

- 同一面板更名为「持续训练：教师 / 自主」，模式选择明确说明新增标签/历史教师使用情况，提供自对弈时间、探索概率和历史教师权重；停止后仍保留选定模式，只有用户显式选择才切回教师。
- `teacher_exit_evidence` 事件把模式、实际训练来源、无教师可运行性和历史测评报告关联；只有历史挑战确实晋级，才标记相对进步已有证据。没有固定样本量毕业条件，不要求战胜 Rapfi。
- 新增 `tools/selfplay-task.example.json`；CLI 和 GUI 共用后端。没有启动生产长任务，没有切换用户现任版本。
