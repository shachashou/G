# 05: 持续采集与滚动样本池

**What to build:** 用户从客户端启动采集后，系统持续产生多样合法局面、筛选打标并写入有容量上限的训练样本池，可查看有效吞吐、过滤、去重和留存状态。

**Blocked by:** 04 — 教师评分与有效样本落盘。

**Status:** done

- [x] 使用明确的采集策略与版本身份自动产生多样开局和中盘，复用权威规则、战术筛选和教师适配；无需已训练的新模型即可生成启动数据。
- [x] 按可追溯对局或采样来源提交完整数据；未提交、未校验或半写入分片不能被训练者读取。
- [x] 样本池容量、启动样本量、新旧混合策略、探索配置及采集速率可配置，并记录本次运行的实际值。
- [x] 按明确策略去重、控制重复并逐步淘汰旧数据；正在读取的分片不被原地删除，采集过快时有背压或暂停。
- [x] 对局级验证身份独立冻结，检查 D4 等价局面泄漏；追加和淘汰训练数据均不改变验证成员。
- [x] 数据契约能够承载教师标签和后续自主对局结果，按来源区分并允许只存在其中一种有效监督，不在本工单提前实现自主训练。
- [x] 分别显示累计生成、有效、去重后有效、当前池容量、过滤原因和有效样本每秒；不把对称增广计为独立原始数据。
- [x] 少量有效数据即可供下游读取，不设置必须先收集数百万条的限制。
- [x] 在小容量配置下完成真实采集、入池、读取与淘汰演示，停止后不遗留采集和教师进程。

## Verification

在采集任务与样本池读写公共边界验证完整性、容量、并发读取和淘汰、重复控制及防泄漏。小规模实测报告有效吞吐，不外推为最终棋力结论。

### 验收记录

**采集策略与身份**

- `tools/collect.py`：用当前引擎自我对弈（未训练模型时为手工评估，`model_id=handcrafted`）。开局在配置区域内随机落子（`opening_plies`、`opening_region`），其余按固定深度 `depth` 搜索；每 `sample_every` 手抽取一个候选局面；策略版本 `collect-v1`，模型身份随对局写入。
- 每局来源 id 形如 `collect-v1-<seed>-<index>-<nonce>`；配置快照（局数、深度、最大手数、开局手数/区域、采样间隔、教师预算、容量、验证局数、去重策略、新旧比例、限速、种子）写入 `runs` 表，运行结束时补上实际生成/有效/入池数与耗时。
- 无需已训练网络即可启动；教师缺失时采集入口明确失败，不静默生成无标签数据。

**提交与可见性**

- 对局先 `begin_game` 暂存；样本逐个 `add_sample`；`commit_game` 在一个 `BEGIN IMMEDIATE` 事务里把状态改为 `committed`、写分片身份（验证/训练）并执行容量淘汰。
- 读取只 `JOIN games ON status='committed'`，暂存行对读取者不可见；`abort_game` 删除暂存对局；采集中断或异常同样丢弃，读取者永远看不到半写入数据（测试覆盖 staged 不可见、abort 后不可见、停止后 `staged_games == 0`）。

**去重、容量与淘汰**

- 精确去重：`dedup_key = sha256(board|side)` 唯一索引；默认再做 D4 规范形去重（`d4_key` 取 8 种变换的最小值），对称增广不计为独立原始数据（`d4_augmentations` 恒为 0，重复被记为 `d4_duplicate`）。
- 容量按样本数计；提交后若超限，按 `committed_at, id` 从最旧的**训练**对局开始整局淘汰，验证对局永不淘汰；只剩验证对局时记录溢出而不删除。
- 实测：容量 80 的采集池中 7 条样本；把容量降到 4 后 `evict` 淘汰 1 局/4 条训练样本，3 条验证样本保留，`validate` 通过。
- 读取使用 WAL 快照（`read_snapshot`）：另一连接提交并淘汰时，持有快照的读取者两次查询行数一致（测试覆盖）。
- 背压：`--throttle-ms` 在池利用率 ≥ 95% 时暂停采集；本工单只提供机制与配置记录，未在真实高负载下压测。

**验证集冻结与 D4 泄漏**

- 验证成员在首批样本入池时写入 `meta.validation.source_ids` 并记录 `frozen_at`；后续提交只补训练集，追踪/调用/淘汰都不改变成员列表（测试覆盖两次追加后成员不变）。
- 验证样本的 `d4_key` 写入 `validation_keys`；训练样本若与验证局面 D4 等价会被删除并计数 `d4_leak`（默认 D4 去重时在插入阶段即被拦下；测试关闭 D4 去重专门验证泄漏删除路径）。验证样本本身从不被删除。

**数据契约与监督来源**

- 样本区分 `label_source`：`teacher`（带归一化 value）、`selfplay_result`（带 result_value）或 `none`；`CHECK` 保证 teacher 必须有 value、结果监督必须有结果值。本工单只产生教师监督，结果监督列与约束已就绪，留给自主训练工单。
- 每条样本保存棋盘、行棋方、战术状态、标签版本、教师身份与预算、来源对局、模型身份；对局保存真实结果或 `NULL`（未完成/被截断），不伪造和棋。
- `final_result` 与 `value` 分列，教师标签和最终胜负可分别存在。

**统计**

- `stats` 输出：累计 `generated`、`valid`（通过筛选与验证、进入插入阶段的样本）、`inserted`（去重后入池）、`duplicate`、`d4_duplicate`、`d4_leak`、`evicted_games/samples`、`pool_samples`、`train/validation_samples`、`capacity`、`filters` 按原因拆分、`effective_per_second`、`validation_games`、`d4_augmentations`、`staged_games`。
- 采集运行把 `elapsed_seconds` 与 `effective_per_second` 写入 `runs`，GUI 与 CLI 读取同一份计数。

**GUI**

- 「持续采集」面板：局数、容量、教师预算可设；「启动采集」在后台线程用独立执行器与教师进程运行采集（不干扰当前对局），实时显示生成/有效/入池/池容量/有效每秒/过滤原因；「停止采集」置停止标志，当前对局被 `abort`，线程退出后按钮恢复。
- 关闭窗口会请求停止并等待采集线程结束；教师缺失时错误区明确报错且不启动。
- 状态区显示样本池容量与训练/验证样本数。

**实际执行**

- 真实小批量（Rapfi 250615，`--games 2 --capacity 80 --validation-games 1 --depth 3 --max-plies 40 --sample-every 3 --budget-ms 200 --seed 42`）：
  - 生成 **26** 个候选；**7** 个通过筛选并全部去重后入池；有效 **1.97 样本/秒**（3.58 秒）。
  - 过滤原因：`mate 11`、`no_score 6`、`vcf_proven 1`、`game_over 1`。
  - 验证 3 条、训练 4 条；`staged_games = 0`；`validate` 通过。
  - 容量降到 4 的淘汰演示：淘汰 1 局/4 条训练样本，验证 3 条保留。
- 测试：`pool_tests` **39 项**（staged/abort、精确与 D4 去重、容量淘汰、验证冻结、D4 泄漏、并发快照、监督契约、混合抽样、截断/新版本/非池文件拒绝）；`collect_tests` **26 项**（真实执行器自我对弈 + 确定性教师桩、原子提交、计数、停止与进程清理）；`gui_collect_smoke` **15 项**（真实小批量采集、指标、停止、缺失依赖）。
- `ctest`：**25/25 全绿**（原 22 项 + `pool_tests`、`collect_tests`、`gui_collect_smoke`）。
- 小规模数字只用于链路与吞吐核验，不作为最终棋力或长期生产吞吐结论。

**限制与后续**

- 采集使用当前引擎的自我对弈与时间预算教师标签，本工单未接新网络（工单 06/07）；`model_id` 已记录以便后续区分。
- 样本池按单写者设计（采集进程写，训练进程读）；多采集进程并发写的锁竞争未实现。
- D4 去重默认开启，会丢弃对称等价局面；可用 `--no-dedup-d4` 关闭，此时验证侧仍会拦截跨分片泄漏。
- 采集轮次间隔、长期调度和任务恢复未实现（工单 12）；训练读取接口已就绪，但训练循环在工单 06。
