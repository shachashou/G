# 13: 简化界面（接近苹果手机式的简单有效）

**What to build:** 把当前一屏堆满表单的桌面工作台改成简洁、克制、以棋局和当前任务为中心的界面：用户一眼知道现在是什么模式、该点哪个主按钮，复杂参数收进可展开的“高级设置”，视觉风格接近苹果手机应用的留白、字体层级、圆角和单一强调色。

**Blocked by:** 12 — 任务恢复与一站式验收。

**Status:** done

- [x] 建立统一的视觉主题：浅暖中性背景、白色卡片、18–24px 圆角、轻边框/阴影、单一蓝色强调色、清晰的字号层级和足够大的点击区域。
- [x] 主界面只保留一个视觉焦点：左侧棋盘卡片；右侧当前流程的主操作和状态。标题、副标题和当前模型身份在顶部可见，不把全部控件同时铺开。
- [x] 四个模式（玩一把 / 收集数据 / 从0训练·自我训练 / 测评）有明确的主按钮；同一屏同一时刻只有一个主要动作，其余为次要或危险操作。
- [x] 复杂的训练、采集、测评和任务参数收进默认折叠的“高级设置”；展开后功能与数值不变，折叠不影响已有取值和测试。
- [x] 任务状态、池容量、训练进度、测评结论和恢复入口仍可见；暂停/继续/停止/恢复按钮沿用工单 12 的真实状态机。
- [x] 不删除任何既有功能或公共控件属性；现有 GUI 黑盒测试不因界面重排失效。
- [x] 在常见桌面窗口尺寸下主按钮、棋盘和状态不被裁切；滚动只出现在内容超出的地方。
- [x] 新增 offscreen 界面验收：主题生效、四个模式、主按钮可见、高级设置默认折叠、展开后控件可用、模型身份可见、现有完整任务流程仍可执行。
- [x] 更新客户端说明和工单记录，说明主操作、进阶设置和故障恢复入口；不把未实现的行为写成已完成。

## Verification

以 offscreen 真实窗口为最高验收边界，结合现有 GUI 流程测试（对弈、模型、教师、采集、训练、持续任务、测评、恢复）。只验证用户可见结构和既有功能不回退；不修改规则、搜索、训练或协议行为。

### 实施与验收记录（2026-11-11）

**视觉主题**

- 新增 `gui/ui_components.py`：集中定义 QSS 主题与可折叠组件。背景 `#F5F5F7`、白色卡片、`#EDEDF2` 轻边框、18–24px 圆角、`#007AFF` 单一强调色、`#FF3B30` 危险色；字体优先 `Segoe UI Variable` / `SF Pro Text` / `Segoe UI` / `Microsoft YaHei UI`。
- 顶部大标题“五子棋”+ 一行副标题，右侧是当前模型身份 pill（手工评估 / 候选模型 / 正式 vN / 历史 vN / 旧版 NNUE）。
- 棋盘改为白色圆角卡片 + 轻投影；棋盘底色调整为暖中性色，网格和星位降低对比，棋子增加轻投影，合法落点改为更小的蓝色点，最后一手用蓝色圆环。落点几何尺寸和点击行为未变。
- 右侧内容放进无边框滚动区，卡片间距统一，窗口默认 1264×734；右侧模型卡、标签页、卡片内容在 1264 宽下不再横向裁切（固定最小宽度 529，viewport 572）。

**信息层级**

- 右侧保留四个模式标签：玩一把 / 收集数据 / 从0训练·自我训练 / 测评；标签栏采用白色选中 pill，未选中为灰字，不额外加重边框。
- 每个模式只突出一个蓝色主按钮：
  - 玩一把：`新局` 蓝色主按钮，`停止对局` 红色危险按钮。
  - 收集数据：`启动采集` 蓝色主按钮，暂停/停止为次要/危险。
  - 从0训练·自我训练：持续任务 `启动教师训练任务` 为蓝色主按钮；单次 `开始训练` 保持次要按钮，避免同屏两个主操作。
  - 测评：`登记 v0` / `开始测评` 互斥启用（无正式版本时只能登记，有正式版本时只能测评），暂停/继续/停止为次要/危险。
- 卡片标题缩短：模型、对局、采集数据、从0训练、对局状态、记录、自我训练、测评与晋级。
- 训练、采集、测评、任务资源和高级对局设置收进 `CollapsibleSection`，默认折叠，点击 `› / ⌄` 展开；折叠只隐藏，不改变取值、绑定或按钮状态。
- 持续任务面板保留模式选择、提示、主操作、恢复任务行、状态与指标；设置统一收进“任务与资源设置”。历史测评保留候选、主操作、状态与报告；对手和参数收进“测评参数与对手”。
