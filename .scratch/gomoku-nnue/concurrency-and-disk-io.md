# 并发与低写盘实施记录

用户要求充分利用本机 CPU / GPU，并减少磁盘写入。硬件为 Ryzen 9 7950X3D（16 核 / 32 逻辑线程）、约 64 GiB 内存、AMD RX 7900 XTX；现有 Python 3.12 / ROCm 环境可用，无需下载。

## 结果

- 持续任务支持有界多路生产，所有工作线程共享总局数、连续空局和背压预算，单独使用 SQLite 连接；唯一游戏索引决定来源、种子和文件名。盘内固定正式版本，不共享可变棋盘或引擎实例。
- 测评按有界对局队列并行执行，只有主线程更新报告，按开局与黑白排序保存；双方仍单线程 / 等时间 / 同开局换色。异常取消兄弟任务，不把引擎异常误写为用户停止，不放宽晋级门槛。
- GUI 默认高吞吐，可切回少量数据启动：本机 24 路采集 / 8 路测评 / PyTorch CPU 4 线程 / GPU 批 2048；池容量 100000、训练快照 32768、启动 / 新增训练样本 2048、积压 8192、验证对局 8。可逐项调整；学习率和步数不因预设改变。
- 特征编码只做一次，设备端抽样和 D4 变换与旧路径保持 RNG 顺序、特征、目标和样本权重完全一致。特征缓存上限 256 MiB；大型输入保留逐批路径。
- 普通状态 / 测评报告最多每 2 秒合并写入，GUI 接收内存进度；终态立即保存。阶段日志记录摘要。训练历史每 2 秒批量追加。
- 周期 checkpoint 至少间隔 60 秒，最佳状态先深拷贝冻结在内存，结束 / 停止保存准确的最佳与最后状态。减少写入会降低异常断电恢复粒度，不宣称每 60 秒必有恢复点。
- 样本按盘批量暂存；D4 去重与写入共用 `BEGIN IMMEDIATE` 防止并发检查 / 插入竞态。批次错误完整回滚，`commit_game()` 仍是可训练边界。生成 / 过滤计数按盘批量写入，保留 SQLite 原有同步持久化设置。完成的自对弈棋谱只写一次。

## 验证证据

- 回归覆盖：3 路真实采集与训练 / 历史测评、全局 7 局上限与唯一来源、4 路停止进程回收、并发测评确实重叠与停止保留现任、4 路发布前完整棋谱重放、CPU / AMD GPU 批次等价。
- 写入断言：100 次进度更新只触发 1 次普通状态保存，停止立即保存最后进度；8 步训练每步验证 / 请求 checkpoint，只保存最佳与最终两份；8 条样本批次只提交 1 个事务，错误批次全部回滚；64 局测评在长写入间隔下只保存初始与封存报告。
- 最终全量 CTest **38/38 通过，无跳过**（176.65 秒）；高吞吐示例配置校验、Python 编译检查和 `git diff --check` 通过。
- 本机真实隔离运行：`build/acceptance/concurrency-low-io/acceptance.json`，任务 `7b9ef71df912478b85fa211d2d87aa49`。24 个独立游戏索引 / 24 份游戏记录，峰值 33 个任务自有引擎进程；完成 AMD GPU 训练和 8 路测评调度。池校验无错误，退出时无暂存样本，所有进程已退出。实际写入：状态 4 次（包含开始 / 终态）、最佳与最终 checkpoint 各 1 次、测评报告 2 次。未修改生产模型和样本池。
- 对局与导出只做功能验收，不宣称棋力提升。先前隔离尝试 `build/acceptance/concurrency/` 的候选触发数值拒绝，现任保持；随后隔离低学习率功能验收通过，导出与晋级阈值不变。
